## The decisive normal fallback

`PanelWorkspaceRootConsumer.panelWorkspaceBodyReady` explicitly permits ready=true even when root is null (`renderer/panels/PanelWorkspaceRootConsumer.tsx:4–15`). PanelArea consequently mounts PanelBody (`PanelArea.tsx:465–502`) and passes the current full project independently of cwd. There is no workspace.error branch in PanelArea. PanelBody checks only whether the registry entry exists, then passes project/cwd/sessionMainRootId to its render function (`:643–677`). Files is always enabled (`PanelRegistry.ts:95,104–108`), and its registry adapter passes those same props (`:118–126`). It is not filtered as Review would be.

Inside actual `FilesPanel`, project exists and workspaceCwd is null:

- `mainRootId = sessionMainRootId ?? project.primaryRootId` chooses the live project's primary ID (`FilesPanel.tsx:142`).
- The matching actual primary root is retained, with `path = workspaceCwd ?? primary.path`, hence the real registered primary path (`:143–150`). Other root ID/path pairs are also preserved.
- Default selection resolves that root, and **Files' own** cwd is its activeRoot.path (`:153–176`). It is therefore non-null despite the panel hook's null workspace root. The “select project first” empty-state guard is not entered for a healthy registered project (`:306–311`).
- A missing sessionMainRootId makes the Session-API condition false even though the UI ID is present (`:178`). Actual Files then calls `readProjectDir(project.id, activeRoot.id, dir)` and `readProjectFileContent` (`:187–194`). The initial DirNode supplies the same activeRoot path (`:345–347,461–474`).
- Actual preload invokes fsRoot:readDir (`preload/project-authority-api.ts:100–103`), and Main resolves the matching registry root and reads its matching directory (`main/index.ts:6486–6489` primary / `:6492–6495` latest; `renderer-project-path.ts:73–83`; `fs-service.ts:30–32,52–54`). For project P with primary B, this is **P/B.id/B.path**, not an unknown-session filesystem call and not B.id/A.path.

Thus the full statically traced App materialization path has a supported normal consumer, without suppressing the UI ID, forging Core state, granting Host authority, or requiring a first model send. A transient workspace spinner while the initial IPC settles remains ordinary asynchronous loading. Files' visible project tree preference must of course be open, and the project/root must remain healthy; those normal UI and storage prerequisites are not a newly found defect.

No contemporary promise was identified that this Files tree must expose the no-repo sandbox before a run; that boundary is not promoted to a defect.
