# 修复交接建议（审查结论，未实施修复）

此表用于从已确认的 86 项中安排修复顺序，不新增发现、不调整级别，也不将同批问题视为同一个根因。正式触发条件、源码行号、正常对照与平台限制以 [主报告](README.md)、[流程覆盖地图](flow-coverage.md)及专项附录为准。

| 顺序 | 建议先交付的结果 | 相关已确认项 | 修复验收应保留的场景 |
| --- | --- | --- | --- |
| 1 | 创建失败只能回滚本次调用拥有的资源 | **R35/P1**：[真实 Git 并发证据](desktop-round3.md) | 输入框连续 Enter 与 Main 并行请求都应有一致处理；失败请求不得删除成功请求的 worktree、分支或未提交文件。事前“路径不存在”不足以证明回滚归属。 |
| 2 | 新增账号不覆盖旧账号；用户停止后不再提交旧浏览器输入；worker 退出不带走 Node Host | R42、R81、R36/P2：[凭据](credentials-round5.md)、[Browser Stop](browser-stop-round22.md)、[Host pipe](runtime-round3.md) | 默认名和中文名两次新增保留两份独立记录；取消尚在 readiness 等待的请求后 enable 不产生旧 Input；写入与 worker 退出交叉时 Host 留存并结算请求。保留显式账号更新、已提交动作不回滚和正常退出控制。 |
| 3 | 一次提交有稳定身份，草稿、附件与审批都留在所属会话 | R03、R04、R05、R10、R12、R13、R33、R37、R40、R41/P2：[会话与提交证据索引](README.md) | 丢 ACK 后核对同一意图；后台输出不能抢新会话绑定；离线新建尚未确认项目时不能沿用旧目标；并发/重连审批有独立 request ID；预入队失败稿和新稿均可取回。 |
| 4 | 长任务的接纳、取消、完成和关闭都反映实际执行 | R07、R08、R15、R18、R30、R31、R44、R45、R57、R73、R78、R79/P2：[运行时](runtime-round3.md)、[自动化](automation-round5.md)、[Goal](goal-sleep-round20.md) | 不同 runtime 使用对应 Stop；后台队列不依赖前台选择；终态拒写有可恢复诊断；关闭等待 owned 资源退役；冷 Goal 续接完成合法权威重建并结算 resolved 失败；非 once 续接超时不能误报完成并重复排入。 |
| 5 | 项目、根目录和存储更新保持同一份权威 | R22、R23、R24、R25、R28、R52、R69、R72/P2，以及 R86/P3：[项目恢复](project-recovery-round16.md)、[归档恢复](session-operations-round17.md)、[根映射](file-root-round27.md) | 合法 secondary/worktree 保持可用；单项目故障不清空健康 Panel；资源释放先于权威删除；旧表单不能覆盖他端新字段；新源校验失败保留旧插件；恢复同时写 Core 状态；root ID 与 path 必须来自同一个注册根。保留 trust、owner、symlink 和越界拒读门禁。 |
| 6 | 连接、后台状态及失败反馈能让用户继续操作 | 其余 P2 按正式影响排入；P3 按使用频率处理：[全部编号与级别](README.md) | 慢 peer 不能无限累积发送；认证锁立即区分非争用错误；失败重试保稿、恢复步骤可见；展示覆盖范围与持久状态一致。各项已有正常控制应继续通过，不能用静默吞错作为恢复。 |

上表是基于当前证据的工程排序建议，并非实施方案或已通过的修复验收。现有表征测试通过只证明问题复现；修复时应把对应缺陷断言改为正确行为，并保留正常路径、去重和资源归属控制。平台只在报告已验证的范围内成立，完整 App/真实 worker/模型等未动态执行的边界不能据此当成端到端验收完成。
