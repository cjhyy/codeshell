This is a conservative historical JSON source-row index. It is an aid to choosing a future review target, with no product body review or runtime result.

For reuse, copy this metadata method to a new owned output directory and adjust ROOT/OUT there. Do not rerun into this frozen directory. The prepared [capture script](capture-inventories.py) contains the same capture prefix actually executed once by the [preserved first builder](classifier-first-script.py). It inventories current rg-visible TS/TSX bytes and all docs/bugs MD/JSON bytes, with exact mutable/future exclusions. The [final classifier](build-index.py) reuses those dated inventories, checks every parsed JSON document SHA, and reads source files only through the already captured byte metadata. Its final header wording and compact serialization are prepared metadata formatting; classification was exercised on the same captured corpus. The first summary/builder and [revision notes](classifier-revision-notes.json) preserve the pre-freeze refinement from the broader first draft. No failed product or dynamic direction was retried.

Source inventory respects normal repository rg ignore rules and explicitly excludes .git/node_modules; it is a filesystem snapshot, not a Git tracked set. It includes repository tests/docs TS as well as packages. Line counts use len(bytes.splitlines()). The history inventory uses rg --hidden --no-ignore over docs/bugs MD/MD-uppercase/JSON, includes frozen 42 and excludes exact 43–49 directories. MD files are byte inventory only here. All JSON scalar values are counted recursively; JSON keys are not counted as searched scalar strings. Keys are consulted structurally only for named row fields and a source-path-key adapter (0 such anchors in this corpus).

A row must contain an exact recognized source path scalar, or an exact source-path map key. Absolute old worktree prefixes normalize only when the remaining complete repository path matches; embedded prose/basenames are not matched. Direct TS-shaped paths include absent historical paths when testing ambiguity. A same-object unique source SHA equal to the dated filesystem SHA is required for active full or selected claims. A locator-suffixed path, multiple direct source paths or conflicting hashes cannot activate full. A narrow ancestor is retained only if its direct row has one clear source path and one unique hash; that hash remains pending and never upgrades full or selected. Artifact/document hashes are not borrowed to activate a source claim.

Coverage/readScope/review/scope and named variants are adapted, including a one-level nested review/scope object or scalar list. Explicit full requires a clear full/file/module phrase or a direct full label, the same-object SHA condition and no contradictory scope. “Full static module” stored in review or scope is therefore retained. Hash/pin/metadata-only, navigation/locator, incidental inventory references, selected/partial/not-full/except/excludes, unsupported ranges, conflicting false review flags and recorded mechanism boundaries never upgrade to full. Role/purpose/note fields can veto an upgrade but cannot provide positive full evidence. Executed fixture or loaded-module lists alone supply no semantic scope.

Selected/read ranges are adapted from numeric pairs or simple text intervals and start/end object forms, and validated against the dated file line count. Displayed/navigation ranges are not semantic selected ranges. Generic ambiguous or unsupported metadata remains unknown. Deduplicated claims retain necessary scope/range/hash fields with provenance references. Each provenance historyRow is a zero-based index into history-inventory.json files; that row stores the document path/SHA once. jsonPointer locates the original historical object or list scalar. This avoids copying historical prose or whole source-row objects. The two larger tables are compact JSON; inspect bounded selections rather than dumping them.

The coverage file statuses are claims about the captured SHA only, not certifications that an old author read correctly. MD-only full evidence is not exhaustive in this index; regex/prose aliases, remote/imported evidence, missing SHA and unsupported schemas can remain unknown. No row means no row in this method, never “unread.” Current full claims do not mean all behavior, native mechanisms or execution were validated. Every suggested target still needs an exact fresh MD+recursive-JSON old-full/scope/cause gate before source reading.
