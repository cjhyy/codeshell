# inspectionScope metadata adapter method

Only this new exact directory is writable. For reuse, copy method.py into another new output directory and adjust ROOT/OUT there. Never run it into this frozen directory or old49/51/56 artifacts.

The pinned49 build-index.py functions for strict source paths, same-object SHA, explicit ranges and baseline classification are copied as metadata code. The adapter adds only the named structured inspectionScope field (including the existing one-level scope/review container adaptation). A new positive must be a clear leading entire/whole/full file/module label or a direct full label. Embedded prose, quoted/raw/original/excerpt labels cannot create the new positive. Original purpose text is retained exactly. The implementation keeps same-object one-source-path/one-unique-current-SHA, locator/list/ancestor binding limits, explicit partial/not-full/navigation/hash/incidental/mechanism-boundary vetoes, range completeness and contradictory read flags. An inspectionScope value without a clear label remains limited/unknown; free-prose line numbers are not expanded into selected coverage.

The original49 classifier and adapter run against the same old49 dated history/source inputs to isolate field recognition. Their current-SHA binding is then computed separately. Later JSON records are split into old49 history, post49/frozen43+44, and frozen45 cohorts. Current file states are reconstructed from the unchanged51 inventory plus35 per-path transitions; no full current inventory or old12MB claims table is copied. Each transition preserves document SHA, exact JSON pointer, source path/SHA and original scope/ranges. Representative provenance prefers canonical source manifests over first/raw diagnostic variants, not an additional read.

Current TS/TSX paths use exactly51 rg-visible hidden source filter and are read only as bytes for length/SHA/splitlines. Fresh history uses hidden/no-ignore MD/MD-uppercase/JSON docs/bugs inventory, includes frozen45, excludes exact46–57 directories. All JSON values/objects/arrays are machine-counted recursively. The old coverage-claims.json is parsed for those counts only; it supplies no new adapted evidence and is not copied. MD text is byte/text inventoried but never auto-promoted to full evidence. JSON keys are structural field/path adapters, not searched scalar values.

Machine traversal is not author semantic reading. Full/selected are author-claim metadata categories for exact bytes, not all-behavior/runtime/native/identity validation. Unknown/no-row is not unread, unfinished or a bug count. Counts are conservative JSON metadata lower bounds, with no percentage. The real corpus exercises the required R13 positive and6limited inspectionScope rows. No synthetic product/metadata fixture suite was run for every veto edge; the code and this limitation remain reviewable.
