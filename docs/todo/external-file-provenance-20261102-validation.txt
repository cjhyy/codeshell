3. 与 CC 方案的偏差及安全修正

A. 没有执行 git status。
真实失败测试证实 filter driver 名可包含 '='，按配置名拼接 -c 关闭过滤器会失效并执行仓库程序；即使屏蔽所有当时已知 driver，config/attributes 仍可能并发变化。
因此采用 ls-files --stage -z + ls-tree -z + hash-object --no-filters + 文件 stat 栅栏完成分类，不调用能触发 clean/process filters 的 status。真实恶意 filter（含 '=' 名称）测试保证没有执行 marker。这是针对 Git 配置执行面的最小修正。
可执行权限也作保守比较；未提交的 chmod 不误记 recorded。

B. contentRef 增加可选 repositoryId（64 位 SHA256）。
它绑定 canonical commonDir + dev/ino/birthtime，而非只绑定 OID 或 worktreePath。新 probe 始终生成；历史 reader 缺少绑定时拒绝读取（repository-mismatch）。该 ID 是仓库关联检验，不是新的权限凭证，授权仍由 Session/project root 决定。
这意味着仓库搬迁、克隆、替换或文件系统身份变化会安全地变成不可用，不尝试猜测迁移。

C. Renderer 使用本地纯校验守卫。
为遵守 renderer 不 runtime import 非 reviewed Core entry 的规则，保留本地 guard，并用 parity 测试约束与 Core 协议一致；未扩展 browser runtime entry。

D. 未提高架构预算。
只合并已有同模块的重复 barrel export 声明，添加要求的类型/函数。architecture-budgets 与精确 export contract 均通过，预算文件和 workflow 无改动。
