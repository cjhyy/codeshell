## 1. 历史基线与本分支范围

此前 9 天的 843 次相邻请求对来自 `gpt-6.1-sol` 线路。损失按当时的请求和缓存读数归因，不能据此推算本分支的长期节省。

| 原因                                 | 历史观察                                                                            | 本分支处理                                                       |

## 2. 根因

此前动态上下文每 run 临时插入、随后移除，导致下一 run 的可复用前缀止于旧动态块之前。技能、记忆等内容又经常变化，整块比较不足以解决问题。

旧浏览器快照折叠、重复 Read 去重和图片占位符会改写已发送的消息。省下几百到几千 token 的一次改写，可能让改写位置之后数十万 token 失去缓存。显式缓存线路只能从仍有效的存档点恢复，不能假设供应商按任意最长公共前缀读取。

旧辅助提示把固定说明、整个对话和每次变化的任务拼成一个用户消息。即使大部分文本相同，也缺少可复用的消息边界；在 Anthropic 显式线路上，还必须在后续请求保留上次实际写入的稳定存档点。

## 3. 已实现的行为

### 3.1 本地持久化的上下文账本

`prompt/composer.ts` 输出带 key 的上下文段；`context/context-ledger.ts` 计算快照和更新；`engine/run-context-ledger.ts` 将其作为带 `contextLedger` 标记的注入消息写入 transcript。

- 首次使用或原账本被压缩、归档、NewContext rollover 移除后，写一份完整快照。后续只追加变化，完全相同则不追加。
- 记忆按稳定条目比较；技能按已知 id 集合比较，避免排名和显示预算变化制造更新。其他能力、来源、Goal 工具状态和 MCP 连接状态按段更新。
- 每条更新自带固定说明，声明新增、替换、移除如何覆盖先前状态；没有为了这一规则额外改写所有会话的系统提示。
- 正文、账本比较状态和提醒实际保存在本地 transcript 中，**没有旁路正文文件**。`session/context-messages.ts` 统一识别本地上下文事件。远程 `session_detail`、协议查询、Hub JSON、Markdown、手机旧历史、外部交接和相关投影过滤它们；`promptSubmitHookMessages` 不进入远程/导出的 state。
- `prompt_rewrite` 和 `context_checkpoint` 也从这些远程/导出事件列表移除：checkpoint 的 `data.messages` 可能包含已经吸收的重写正文，不能只过滤顶层标记。原始普通用户/助手消息继续保留。模型所需的本地 fork、归档、恢复回放保留完整事件。
- 工作区 root 改变时撤销旧工作区账本；撤销标记同时作用于内存历史和本地回放，随后输出新 scope 的快照。

Git 状态单独作为 `snapshot-only` 段，与其他能力文本分开。每个快照周期只发送一次，明确说明这是上次刷新上下文时的快照、不会持续更新、需要实时状态时应运行 git；文本不带时间戳。状态最多 40 行，余量以 `… N more` 表示；最近提交最多 5 条，单条 subject 最多 160 字符。压缩或 scope 改变后的新快照显示当时状态，不累计每个 run 的 dirty tree。

### 3.2 提醒、重写与本地回放

`on_session_start` 的内容与历史中已生效提醒比较；`user_prompt_submit` 的最后输出另存 `SessionState.promptSubmitHookMessages`，使重启后仍能判断是否变化。提醒通过 `hookReminder.beforeEventId` 定位到其用户任务之前，正文和位置在本地回放中保持一致。

`engine/context-reminders.ts` 也持久化 run 内提醒，包括 headless 后台代理完成通知。标记后的提醒不计入用户消息数量，不作为标题生成、记忆提取或 optimization-lab 的真实用户输入。

提示 hook 改写通过独立 `prompt_rewrite` 事件保存；原始用户消息仍是用户输入，模型回放使用最新有效重写。fork 同时重映射普通 event id 和 `<checkpointId>:<index>` 合成 id，保留 checkpoint 后追加的提醒和重写指向。

行为 profile 声明为 dynamic 的 runtime context 仍为非持久 volatile 消息。它不进入账本；显式缓存线路每次请求把它移到尾部，下一 run 可移除。其他 profile 的 system runtime context 继续按原约定放在系统提示。

### 3.3 回溯改写攒批

`context/rewrite-gate.ts` 先计算候选改写，不直接改变已发送历史。重复 Read、旧观察折叠、微压缩和可延迟的图片占位符一批采用。触发条件是：

| 原因       | 实际触发条件                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------- |
| `cold`     | 本进程没有该会话成功请求的 warmth 记录，或距上次成功请求起点超过线路 TTL；任何模型步骤都检查，不限于 run 首次请求 |
| `worth_it` | 默认预计节省达到 `max(4000 tokens, 当前上下文的 15%)`；这是启发式阈值，不是实时供应商价格模型                     |
| `pressure` | 未改写历史达到首次非 micro 压缩阈值，先让便宜清理释放空间                                                         |
| `hard_cap` | 图片等硬数量/体积限制要求立即改写，优先维持请求有效                                                               |

TTL 由有效缓存策略决定：OpenAI explicit/hybrid 为 30 分钟；Anthropic explicit、OpenAI implicit 和 provider-managed 为 5 分钟。成功的主请求更新进程内 warmth，辅助调用不更新主循环 warmth；注册表有界，不跨进程持久化。

写入时的大结果预览、硬截断和单条预算保持原有即时处理；安全脱敏不等待缓存时机。摘要、窗口、归档等必要上下文重建仍可改变历史，并登记前缀变化。

### 3.4 定型线、内容形状与兼容性

`engine/stable-prefix.ts` 按消息对象身份定位定型线：有待处理改写时取最早待改写消息之前；没有时取 run 开始处；引用已被压缩移除时采用可确定的回退边界。

volatile runtime context 限制定型线不能越过它。它位于请求尾部时可把稳定范围推进到尾部之前；**如果待改写边界更早，取两者较小值**。稳定断点与滚动/历史断点共同保留可恢复的存档点。

OpenAI-compatible 显式线路把非空文本统一提升为 text-part 数组，与是否刚好带 marker 无关；纯文本助手回复在本地 live history 和新 transcript 中使用相同的字符串形状，避免恢复造成表示漂移。`assistant-history-content.ts` 统一 live 和持久化表示，包含工具或 reasoning 的块在两条路径都保留。

兼容网关返回符合现有 API 错误分类模式的 400 时可重试一次：拒绝显式缓存字段会关闭该客户端显式策略；拒绝 `content` 数组形状会为该进程的对应 provider/endpoint/model route 记住 string-only fallback，关闭提升和显式标记。后续新客户端也继承该 route 的形状回退。effective-strategy 回报使引擎使用实际策略，避免下一 run 按原显式布局错误移动 volatile context。affinity key 的兼容回退独立处理。没有通过任意自然语言正则猜测错误。

### 3.5 诊断与前缀守卫

`engine/prompt-cache-diagnostics.ts` 使用进程内密钥生成 HMAC，记录系统、工具、配置和逐消息摘要，识别第一条变化消息及其 role/tool-result 属性。状态有界且只在内存中保留，**没有跨重启的诊断旁路文件**。

`testing/prompt-prefix-guard.ts` 由各测试 suite 显式安装；生产未安装时报告是轻量 no-op。改写登记和消息离开通知都以 session id 隔离，一个会话的压缩不能豁免另一个会话。守卫按精确内容形状比较，不把字符串助手回复与 text-block 数组一概视为等价。

指令 head 的诊断仅在守卫安装时计算 SHA-256，不存正文，最多保留 128 个会话。指令文件仍会重新读取，内容变化登记为 `user_context_head`；**没有将指令文件冻结到整个压缩周期**。

### 3.6 日期、头部与权限变化

指令 head 中的日期固定为会话开始日，跨午夜通过账本追加带 supersedes 说明的新日期。指令文件、权限、工具资格等语义和安全变化继续生效；不能为了缓存冻结撤权或保留旧工作区上下文。模型、工具或配置前缀真正改变时仍可能导致缓存失效，并由诊断记录。

### 3.7 辅助调用布局

`engine/aux-prompt-cache.ts` 为同一会话的 memory-extraction、session-summary、memory-write-decision 使用不同 scope，并标记 `scopeKind: auxiliary`。OpenAI-compatible 主会话与辅助调用各有独立的有界 `PromptCacheHistory`，辅助流量不会驱逐主会话存档点。

记忆提取和摘要把固定说明放在最前；对话按追加不变的位置封成约 2000 字符以上的消息段，未封口的最新对话、变化中的列表和任务要求放尾部。显式线路发送这些独立消息并标记稳定边界；非显式线路保留完整单条用户消息，仍使用独立 affinity scope。

写入决策先发送最多 120 条现有记忆的 metadata catalogue，按创建顺序和稳定键排列；candidate、相关 id 排名和正文摘录放在后面。相关列表最多 40 条；正文先脱敏，每条最多 1500 字符、合计最多 8000 字符。UPDATE/DELETE 只能命中相关列表中实际给过正文摘录的目标；只在 catalogue 中出现或正文预算耗尽的目标退回确定性决策，手动记忆保护继续生效。

Anthropic 显式辅助调用额外记住**上次成功请求实际写入的稳定末尾**，下一请求先校验可复用前缀，再同时提供此前读取点和本次稳定末尾。系统、工具、稳定/历史/滚动 markers 总量不超过 4；有工具占槽时优先保留前次读取点，必要时省去滚动尾部。该修复有连续辅助请求的 wire-level 位置断言；第 7 节 Sonnet 历史数字采于此修复之前。

## 5. 验证方式

离线断言是合入门槛：跨 run、磁盘恢复、NewContext、工作区撤权、Git 快照、提醒去重、hook 重写、fork、图片/快照攒批、稳定断点、辅助请求 wire markers，以及各远程/导出路径使用独特 canary 的隐私回归。不能仅凭共享过滤函数测试宣称所有出口安全。

使用隔离 HOME 的 guarded runner；依赖用 bun 安装；最终还需完整 CI partitions、workspaces typecheck、变更文件 lint 和精确 PR head 的必需检查。历史线上样本不替代最终代码的验证，未授权的新付费 API 测试不在本次收尾范围内。

2026-11-13 收尾离线检查：完整 build、全部 workspace typecheck、Host/Link 测试 typecheck 和 lint 通过；lint 保持已有的 90 条 warning。架构预算检查没有提高上限：合并已有的同源 type/value 导出后，内部入口仍在原预算内。完整 ToolSearch、volatile/stable-prefix、架构/导出契约套件分别通过 53、13、10 项，覆盖审查中发现的旧措辞断言、旧边界断言和导出预算回归。

本机尝试了全部 44 个 CI 分区，结果为 19 个通过、22 个失败、3 个未完成；三个中断分区未执行到的所有文件另以独立 guarded 进程尝试。未完成的原分区仍记为未完成，不能用补跑计数宣称全绿。受限 macOS 宿主的 DiskManagement、监听端口、Seatbelt 和原生进程条件造成多项失败；主要失败类别已在 `006bee8c5` 的独立源码快照复现，但尚未独立归因的失败不能一概称为基线问题。依赖安装也遇到 registry 连接限制，本机验证使用审计过的独立依赖副本。这些结果不替代精确候选提交的必需 PR CI，尚不具备合入验收结论。

## 8. Known limitations

- 降级到旧应用版本可能回放已撤销工作区上下文；旧 TUI `/resume` 会显示账本消息；旧手机 output-history 恢复不接受 `prompt_rewrite`。这些旧客户端不具备新过滤/回放规则，不能依靠新版本保证旧版行为。
- Cache warmth、route 兼容性记忆、辅助边界和诊断均不跨进程保存。重启可能让待处理改写按 cold 执行；真正供应商缓存是否仍热只能由实际请求决定。
- 记忆提取对话预算最多约 30k 字符，窗口每次跨约 10k 字符推进，因此推进后通常看到约 20–30k 字符；不是完整会话。大单条消息还有自身摘录上限。
- turn-limit 等已持久化提醒在重启后仍会回放，可能描述此前 run 的限制；当前没有专门的提醒过期协议。
- 指令文件没有整周期冻结。指令、权限、模型或工具语义变化可合法打破前缀，守卫登记不是避免失效的保证。
- 累积账本更新没有独立的“达到全量两倍即重整”门槛，仍由正常压缩、归档、scope 撤销或 NewContext 开启新快照。
- 辅助对话窗口移动、已有 catalogue 元数据更新/移除和 120 条选择范围变化可改变前缀。辅助调用频率未改为只在空闲时执行，也没有把其提示并入主模型请求。
- `context_checkpoint` 在远程/导出时整体省略；保留原始普通事件，不向远程传递内部模型上下文快照。本地 fork/归档/恢复仍有完整 checkpoint。
- 长会话、浏览器密集任务、真实 TTL 边界及长期成本仍需独立样本；OpenAI Responses API 迁移不在本次范围。
