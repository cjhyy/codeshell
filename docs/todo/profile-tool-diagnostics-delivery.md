# Profile 外部工具依赖诊断

2026-10-10，源码修复，尚未发行。

`planProfileRequirements` 在调用任何工具探测前，使用现有 requirements schema
校验完整声明。旧的 `string | null` 探测回调保持兼容；Host 可返回结构化结果，区分
命令不存在与执行失败。

Desktop 只信任在现有 10 秒限制内成功退出的版本输出。非零退出、启动失败及超时
显示“版本探测失败”，保留要求的最低版本和安装提示；成功输出无法解析版本时，
显示“无法确认版本”。正常低版本、满足要求及未声明最低版本的可用性检查保留。

这些是现有依赖确认流程中的诊断。用户仍可确认后继续，或取消；没有新增 Core Run
硬门禁，也不自动安装外部工具。Skill 安装仍使用原有审阅和确认流程。此修复不代表
插件版本授权、其他依赖系统或全部 Profile 后续已经完成。

验证使用私有 HOME、清除继承凭据并在 Core 导入前拒绝 HTTP 请求：

- 原实现的 Core / formatter 出现 11 项预期失败。
- 实际 Node 进程的 6 个 CLI 场景中，原实现出现 4 项预期失败，2 项版本对照通过。
- 重建 Core 后，5 个定向测试文件共 99 项通过，零失败；其中的实际 Node 子测试
  6 项全部通过，包含真实 10 秒超时、非零 stderr、EACCES 和正常版本对照。
- CLI 脚本验证限于 POSIX；Windows 跳过该原生 fixture，不宣称已经验收。

上述结果没有使用真实第三方账号、远程安装或服务器配置。
