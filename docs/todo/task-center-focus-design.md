# 桌面任务中心 Focus 技术方案

2026-11-20 · 设计稿，待实施。适用于本地桌面任务中心。Host 的进程边界、授权数据根、分页与 SQLite 迁移沿用 [0.12 总体方案](desktop-host-runtime-and-storage-0.12.md)。

## 用户打开 Focus 会看到什么

首页按**事项**回答三个问题：在做什么、完成得怎样、用了多少。以“发布 0.12”为例，开发、Windows 测试、macOS 签名分散在三个会话。首页可以显示“改动已合入，Windows 测试通过，macOS 签名待验”，并列出三个关联会话和已知用量。点开某条进展即可回到对应会话、运行或产物。原有“后台工作”视图继续承接逐次执行的查看、取消和重试。

首次使用时，从当前有权查看的普通会话和后台执行列出尚未归组的工作。用户可选中相关会话创建并命名事项，也能按一次运行或一段消息关联、移出。显式委派、已知的父子运行，以及来源类型、来源 ID 和 attempt 均相同的记录，可直接展开。无显式关系的会话由用户确认归组，包括模型根据目标和交付物给出的建议。同一目录、相似标题不足以建立归属。[后台工作筛选](../../packages/desktop/src/renderer/task-inbox/taskInboxViewModel.ts#L81) · [任务来源和运行身份](../../packages/desktop/src/main/task-inbox/task-inbox-types.ts#L28)

事项详情按“已交付、进行中、待确认或阻塞”展示，每条结论附可打开的依据。有明确验收清单时显示“完成 2/3 项”。只有验收条件满足或用户确认时，整件事才显示完成。一次会话退出只更新该次执行状态。TodoWrite 可提供会话内部的清单，Mimi 可提供某次委派的目标、结果和产物。[TodoWrite 的作用域](../../packages/core/src/tool-system/builtin/task.ts#L4) · [Mimi 的事项与尝试](../../packages/pet/src/long-task.ts#L97)

## 数据归属与查询

| 数据 | 谁保存、如何更新 |
| --- | --- |
| 执行事实与证据 | 会话、Run、Mimi、外部 CLI 及其他任务来源继续保存原件。Focus 引用来源类型、来源 ID、可用的 runId、attempt 或消息定位符及版本。来源缺失时展示“来源暂不可用”。打开证据和控制运行时重新校验权限及执行者。 |
| 用户决定 | Host 按桌面授权范围保存版本化的事项文件，记录稳定事项 ID、标题、已确认或排除的关联、验收项和手工完成状态。变更携带预期版本，串行校验并原子写入，落盘后回执。并发冲突时返回最新版本供重试。排除关联在重建后继续生效。 |
| 读索引与摘要 | SQLite 可从事项文件、来源和用量回执重建列表、计数及归属。摘要是可丢弃的派生数据，缓存键包含授权范围、事项、输入材料版本、模型及提示版本。授权缩小或来源删除时撤下涉及它的摘要并重新筛选可见事实。 |

Renderer 经 preload 向 Host 读取同一版本的事项页、计数和详情。页面只订阅版本变化，按需翻页。查询、归组变更、生成摘要使用独立入口，读取列表或用量不会触发模型。Host 从窗口连接取得授权范围，对源记录逐一校验。模型和 Renderer 提供的来源 ID 都必须在本次可见集合中。切换账号、项目授权或数据根时使旧游标和生成请求失效。[现有任务列表与动作契约](../../packages/desktop/src/main/task-inbox/task-inbox-types.ts) · [任务中心实施记录](../superpowers/plans/2026-09-01-local-task-center.md)

## 模型只在 Focus 可见时运行

1. 用户主动打开 Focus 时，先返回本地事实和有效缓存。每次打开至多自动提交一个批次，材料取自当前页需要摘要的事项，以及可建议归组的可见会话。首次打开、尚未建立事项时，也可用本页未归组的会话提出建议。归组建议按候选来源 ID 集合及其材料版本缓存，和事项摘要共用预算。材料未变化且有有效缓存时新增调用为零。
2. Host 在派发前确认该窗口仍展示 Focus，先后两次打开有不同的视图标识。多窗口在同一授权范围请求同一份材料时共用在途结果。页面保持打开期间出现新进展时先更新本地事实，用户点“更新摘要”才发起下一批。
3. 每批设输入和输出 token 上限，优先传目标、变化的验收项、结果或阻塞、产物引用和必要短摘录。超过预算的事项继续显示本地事实，可另行点选。worker 用无工具的辅助模型调用并接收取消信号。返回的每条结论要带来源引用，引用无效、输出截断或调用失败时保留本地事实。[现有无工具摘要调用](../../packages/core/src/engine/auxiliary-pipeline.ts#L51)
4. 切页、最小化、关窗、Renderer 断连或撤权时，Host 撤销对应订阅。最后一个可见订阅撤销后清空该批排队工作，中止在途调用和后续重试。迟到的响应只更新应记录的用量。Host 重启后等待新的可见视图。启动、定时任务和后台输出都不会为 Focus 发起模型调用。

## 用量怎样算到一件事上

首页每件事显示**任务执行用量**。详情可按会话、模型、供应商和日期展开，显示输入、输出、总 token、已上报的缓存读写及预估费用。缓存 token 是输入明细。同一时间段另列 **Focus 分析用量**，包括本次刷新和累计开销。统计、筛选和回看都读取本地账本。查看耗时时使用有起止时间的运行记录，并行运行的事项历时按首次开始至最近结束计算，仍在运行时截至当前。[账本字段与汇总维度](../../packages/core/src/cost-ledger/types.ts#L20) · [现有用量页面](../../packages/desktop/src/renderer/activity/UsagePage.tsx#L50)

- **按回执归属。** Host 在授权数据根内以 `namespace + requestId` 去重，按执行自己的记账会话、runId 和已知的子执行关联取回执。父子会话和委派卡引用同一请求时只计一次。会话涉及多件事而回执只精确到会话时列入“共享或未归属”。调整事项关联只重新计算归属。[现有账本筛选](../../packages/core/src/cost-ledger/store.ts#L473)
- **给 Focus 单独记账。** 扩展 Core 的用途枚举和持久化校验，增加 `focus_summary`。为授权范围内的一次分析建立独立记账身份和批次 ID，将每次发出的模型请求关联至该批次。生成三个事项的一份摘要只记一个批次，发生重试的每次实际请求都计入消耗。现有 Desktop 辅助调用会将账记到单个来源会话，跨事项分析需单独接线。[用途与回执](../../packages/core/src/cost-ledger/types.ts#L3) · [Desktop 辅助调用归属](../../packages/desktop/src/main/auxiliary-model-tracing.ts)
- **标明精度。** 原生 API 按已发出的请求计数，外部 CLI 按已报告的提交轮次计数，一轮可能覆盖多个模型。统一 Focus 和用量页的来源分类，兼容历史的 `external-cli-memory` 回执。费用采用回执的价格快照。无单价、发送后中断且无用量、旧会话缺账分别显示费用未知、用量未知或历史不完整。仅汇总有凭据的数值。[CLI 回执](../../packages/desktop/src/main/external-runtime-usage.ts#L5) · [费用计算](../../packages/core/src/cost-ledger/pricing.ts#L6) · [历史覆盖检查](../../packages/desktop/src/main/usage-history-service.ts#L21)

按同一授权范围和日期验算：各事项独占执行用量合计 + 共享或未归属执行用量 + Focus 分析用量 = 账本已知总量。覆盖缺口与已知小计同时呈现。

## 实施顺序和验收

| 批次 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 1　本地事项与进度 | 接入会话及任务分页，交付手工归组、明确父子关联、证据跳转和本地持久化。沿用 Host P1 的首屏分页、P2 的授权契约，再接 P4/P5 的会话与任务索引。 | 关联三个会话能打开各自的交付依据，一个会话结束后仍显示未完成的事项。重启或清空派生索引后手工归组和排除仍在。两个数据根含同名会话时只能查到各自记录。 |
| 2　用量归集 | Host 建立回执归属索引，接入按事项、会话和期间的用量查询。首版即可只用本地数据。 | 父子重复引用、多事项共享会话、CLI 整轮和缺价格四种样本均可与账本对账。翻页和切换日期的模型调用数为零。 |
| 3　可见时摘要 | 接入可见订阅、预算、缓存、无工具模型调用及独立记账。 | 关页期间回放 1000 条事件，Focus 发出 0 个请求。首次打开尚无事项时可建议归组，用户确认后才保存。两窗口查看相同材料只触发一批，重开命中缓存为 0 次。只改一项时仅发送该项变化及必要上下文。关掉最后一窗后无后续派发，中断的已发送请求保留已知用量或标未知。 |

各批可独立验收。摘要故障或关闭时，事项、证据和用量仍可查询。升级后原版仍可读取既有任务历史，重新升级可恢复已确认的事项关联。0.12 性能主线的发布验收沿用总体方案。
