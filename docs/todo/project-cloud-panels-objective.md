可以。把前面讨论统一起来，目标是：

**同一个 Panel，可以用于本地项目或云端项目；项目决定文件、数据和任务在哪里执行，电脑和手机都能进入项目继续操作。Link 独立提供第三方连接与授权服务。**

下面是总实施清单。现状依据前面核对的源码和已有记录，不代表最新代码已经重新部署验收。

**一、最终需要具备的产品能力**

| 操作方式目标行为     |                         |
| ------------ | ----------------------- |
| 电脑使用本地项目     | 本地执行、本地保存，不依赖云端控制服务在线   |
| 电脑使用云端项目     | 连接云端执行环境，文件和任务留在云端      |
| 手机使用本地项目     | 远程连接电脑，操作同一项目、Panel 和任务 |
| 手机使用云端项目     | 连接云端，电脑关闭也能继续使用         |
| 本地／云端访问第三方服务 | 通过本地连接或独立 Link 服务取得授权数据 |
| 切换操作设备       | 继续访问同一项目，不自动复制文件或迁移任务   |

**二、已有基础与主要缺口**

| 模块已有基础还需要完成 |                      |                           |
| ----------- | -------------------- | ------------------------- |
| 本地执行        | Desktop、Worker、本地项目  | 原生桌面连接云端项目                |
| 云端执行        | Node Hub、Docker、项目容器 | 稳定部署、完整 Panel 验收、后续控制服务整合 |
| 手机入口        | 桌面配对、远程 Web、Hub 工作台  | 环境切换、手机业务流程、稳定远程连接        |
| Panel       | 安装、项目绑定、资源和任务接口      | 功能对齐、项目版本锁定、手机适配          |
| 后台任务        | 已有持久任务服务和部分恢复能力      | 全部长任务脱离页面、跨设备恢复一致         |
| Link        | 宿主内连接管理              | 独立服务及完整上下游授权              |
| 仓库与发布       | 主仓库、独立 Panel 仓库      | 服务仓库边界、版本化依赖、独立部署产物       |

**三、项目模型与连接路由**

这是整个方案的基础。

- 为执行环境建立稳定身份，区分电脑和云端环境。
- 客户端用“环境 ID＋项目 ID”定位项目。
- 统一项目名称、执行位置、在线状态和能力描述。
- 保留桌面与云端已有注册表，通过适配器提供一致操作。
- 手机只提交受授权的项目身份，由 Host 解析实际目录。
- 所有上传、保存、审批、取消操作固定目标项目，切换页面后也不能发错位置。
- 本地项目断线时明确显示离线，不自动转到云端。
- 项目数据仍由所属 Host 管理，不要求全部上传到中央服务。

**四、Panel Host 与功能对齐**

Panel 保持同一套业务实现，Host 处理环境差异。

- 整合桌面和服务端共享的授权、存储、资源、进程、任务服务。
- 保留现有接口兼容及数据布局，逐步迁移调用。
- 统一能力探测、错误、事件和资源限制的表达。
- 文件选择、上传、下载、录音、预览等由对应设备／Host 提供适配。
- 模型、业务流程、处理脚本、依赖安装策略继续归 Panel。
- 明确跨平台程序要求；针对只支持特定系统的引擎提供适配或经过验证的等效方案。
- 以完整操作结果判断功能对齐，不能只通过隐藏按钮或“页面能打开”验收。

现有 [Panel Host 整合方案](/Users/admin/Documents/个人学习/代码学习/codeshell/docs/todo/panel-host-integration-and-server-isolation-2026-09-18.md)继续作为基础。

**五、Panel 版本与项目绑定**

当前项目只绑定 Panel ID，宿主仍统一管理安装版本，需要补齐：

- 同一项目的电脑、手机页面加载同一个确定安装版本。
- 页面与后台程序使用匹配的包内容。
- 项目记录 Panel 版本及内容摘要。
- 安装包支持不可变存储，后续实现多版本共存。
- 不同项目可以独立安排升级。
- 任务记录启动时使用的 Panel 版本。
- 更新处理活跃任务、权限变化及文档格式迁移。
- 保留旧项目数据，提供可验证的升级和恢复路径。

第一阶段可以在受影响任务结束后升级；多版本并行运行随后实现，不能提前承诺。

**六、项目数据、资源与后台任务**

这部分决定能否真正跨设备继续使用。

- 工程、素材、队列、历史和结果保存在项目 Host。
- 需要继续编辑的草稿同步到项目；滚动位置等界面状态留在设备。
- 多设备编辑采用版本校验，避免静默覆盖。
- 长任务交给后台，提交后返回稳定任务 ID。
- 请求重试识别重复提交，执行结果不明确时先查询状态。
- 重新打开页面先读取任务快照，再接收后续事件。
- 关闭页面、断网、撤销授权、取消任务、停止项目分别定义行为。
- 需要无人值守的 Panel 工具提供后台入口，页面和 Agent 共用。
- 输入资源完成交付后再启动处理；输出进入项目资源存储，再提供预览或下载。
- Host 重启后的中断和重试明确可见，不盲目重放有副作用的操作。

**七、手机工作台与电脑远程连接**

分为基础可用和连接体验整合两步。

基础可用：

- 保存并选择“我的电脑”“我的云端”入口。
- 分别完成电脑配对和云端登录。
- 打开项目、Panel、任务、审批和结果。
- 持续显示当前项目及执行位置。
- 支持从手机上传、从项目选素材、下载到手机。
- 适配触控、窄屏、软键盘、横竖屏和长列表。
- 验证锁屏、切换应用、弱网及重开恢复。

随后完善：

- 稳定的电脑远程地址和设备身份。
- 主机主动连接、在线状态、重新连接及设备撤销。
- 统一设备／项目目录与安全中继。
- 任务完成、失败、等待审批的通知。
- 电脑原生窗口进入云端项目。

手机原生 App 外壳可以后置，先完成现有 Web/PWA 流程。

**九、独立 Link 服务**

这是新增服务，不能把当前宿主 Link 管理算作已经完成。

- 独立启动入口、管理页面、配置和持久存储。
- 首版单 owner，支持多个明确选择的第三方连接。
- 上游授权、账号识别、凭据保存及服务商支持的刷新。
- 下游应用登记、授权同意、令牌签发、刷新和撤销。
- 按应用、连接、操作和数据范围检查权限。
- 第三方原始凭据留在 Link，项目只取得受限访问授权。
- 本地 Host 和云端 Host 接入同一个远程 Link 契约。
- 保留现有本地连接方式，不强迫用户迁移。
- 验证重启、授权过期、撤销和在途请求处理。
- Link 故障不阻断不依赖它的项目功能。

先完成一个第三方服务的真实只读闭环，再扩展服务商。依据[独立 Link 设计](/Users/admin/Documents/个人学习/代码学习/codeshell/docs/todo/link-server-oauth-architecture.md)推进。

**十、云端服务与部署**

已有 Hub 可以作为个人部署起点，需要把交付做完整：

- 固定源码版本、构建产物和运行镜像。
- 完成管理员初始化、公开地址和 HTTPS 配置。
- 验证项目创建、启动、停止、文件持久化和重启恢复。
- 配置模型与 Panel 实际需要的程序和依赖。
- 区分控制服务、Link 服务和项目执行环境。
- 分别管理数据目录、凭据、日志、健康检查和资源限制。
- 完成备份、恢复、升级及回滚演练。
- 提供可重复的部署说明和冒烟验证。

目前多项目模式仍采用“宿主机上的 Node 控制服务＋项目 Docker”；整套控制服务容器化是后续适配，不能直接套用现有单工作区 Compose。[当前部署边界](/Users/admin/Documents/个人学习/代码学习/codeshell/docs/project-sandboxes.md)

**十一、仓库与发布组织**

建议采用以下边界，具体迁移分阶段进行：

| 仓库职责                    |                                         |
| ----------------------- | --------------------------------------- |
| `codeshell`             | Core、Desktop、共享 Web、Panel Host、连接与运行基础库 |
| `codeshell-panel-apps`  | Panel 界面、业务程序、依赖、共享客户端 SDK              |
| 新建 `codeshell-services` | 独立 Link、云端控制产品层、部署与运维配置                 |

配套工作包括：

- 明确共享包的公开接口和依赖方向。
- 服务仓库使用确定版本的包，避免跨仓库源码路径依赖。
- 不复制 Core，也不整体搬走桌面正在使用的 `packages/server`。
- 独立生成控制服务、Link 和项目运行环境的构建产物。
- 建立 Host、Panel、服务、镜像的兼容与发布记录。
- 新仓库先承接 Link，云端控制层逐步提取。

**十二、实施顺序与完成标准**

| 顺序主要交付        |                             |
| ------------- | --------------------------- |
| P0：确认基线       | 对齐源码、实际安装包、镜像、部署状态和功能清单     |
| P1：验证架构       | 项目身份与路由＋下载 Panel 在四种组合下完成闭环 |
| P2：补公共能力      | Host 对齐、数据与任务恢复、版本一致性及项目锁定  |
| P3：完成全部 Panel | 各 Panel 手机交互、跨平台执行和完整流程验收   |
| 独立轨道：Link     | 服务仓库、独立授权服务、本地／云端接入         |
| P4：整合连接与交付    | 稳定远程入口、桌面访问云端、部署升级与恢复       |

最终必须覆盖四种组合：

- 电脑操作本地项目。
- 电脑操作云端项目。
- 手机操作本地项目。
- 手机操作云端项目。

每种组合都检查执行位置、实际产物、数据持久化、重复提交、断线恢复、权限撤销和版本更新。
