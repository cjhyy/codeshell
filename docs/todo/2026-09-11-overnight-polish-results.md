## 已复现并修复的主要问题

### 会话恢复和保存

- 取消旧会话恢复后，迟到快照不能推进已应用游标或覆盖当前会话。
- 可选的 Goal 查询不再阻塞聊天历史和已恢复的流式文本前缀。
- 退出时先将合并中的实时事件提交到界面状态，再保存当前和后台会话，覆盖最后 50 ms 事件缓冲和 600 ms 保存防抖窗口。
- 跨窗口快照读取使用读取代次与写入版本共同防护；迟到旧读不能覆盖新读，后续较小读取仍能得到新数据。
- Main 事件流增加进程代次标识，缓存中的序号与代次成对保存、合并，避免重启后的低序号被旧缓存挡住。
- 手机/Web 的同步请求、快照和实时消息也传递 Main 代次；重启后不再以旧游标过滤新消息。前台恢复保留已确认和待确认的新输入，旧连接的迟到数据被隔离。
- 后台会话切回时，保存的 history 与实时 snapshot 若缺少共同游标，保留已保存历史并提示恢复受限，避免把同一回复叠加两次；历史返回后的下一次主回复开始再恢复实时接收。第三次 Main 重启仍保留这道保护。旧版未携带代次的连接、任意长历史的完整接续仍保留在 TODO。
- 加载更早历史时，旧消息前缀插入已知锚点之前，保留另一窗口的新后缀；重复展开保持幂等，随机渲染 ID 改变时仍保留可用的流式文本指针。
- 冷启动实时尾部早于订阅快照到达时，按序号和进程代次重放原始事件并去重；恢复失败或超限时保留当前内容和新输入，阻止不完整状态写回缓存。缺省会话绑定继续兼容旧缓存。
- 在同一进程用两个缓存实例模拟窗口，交替读写执行 100 组共享历史页场景，覆盖早页扩展、随机渲染 ID、重复文本、迟到保存与重复保存；4,000 次消息顺序和幂等性断言通过。此项不是两个 Electron 窗口的真实并发测试。

### 目录锁与主进程稳定性

- 最终导航检查曾出现原生错误弹窗，锁心跳对已消失的 `desktop.lock` 报 ENOENT；关闭弹窗后断言虽通过，该次不作为干净成功。随后同构建独立重跑通过，并继续追查原错误。
- 使用真实 `setTrust` 与 `SessionCatalogStore` 确定复现：信任写入持同步目录锁时等待异步文件操作，同进程会话目录的同步竞争阻塞事件循环约 11 秒，随后错误地接管自己的过期锁，遗留心跳并触发同一报错栈。将有界信任读改写收在不让出的临界区，保留原锁协议和文件检查；修后同探针约 2 ms，无异常。
- 设置保存的异步目录锁与同进程凭证同步写入也能在同一用户目录稳定复现约 11 秒阻塞及 ECOMPROMISED/ERELEASED。该组合使用临时设置和虚构凭证；设置读改写临界区已收为同步，保留合并、损坏文件隔离、原子写入与权限约束。修后同探针约 104 ms（含 100 ms 观察等待），两份数据均保留且无锁异常；21 项测试、52 次断言通过。
- 两个真实审批存储实例同时记住授权时也能复现阻塞约 10.5 秒、第一条记录失败；修后约 51 ms，两条记录都保存。保留文件大小限制、NOFOLLOW、0600 和独占临时文件原子替换。
- Panel 文件存储改为有时限的非阻塞锁重试。两个 Bridge 实例写同一文件，从约 10.2 秒锁失效变为约 145 ms 完成且保留两次写入；锁、权限和配额边界不变。当前 Main 只有一个全局 Bridge，这一项记录为多实例 API 并发边界，不称每个面板各有一个实例。
