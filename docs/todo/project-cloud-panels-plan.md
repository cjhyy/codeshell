# 本地／云端项目、跨设备 Panel、Link：总实施清单

更新：2026-09-24。状态：实施中，尚未发布完整版本。

## 产品原则

同一个 Panel 产品面向本地项目和云端项目。项目决定执行环境、文件位置、数据、后台任务及安装版本；电脑和手机是操作入口。打开同一个项目必须看到同一套项目状态，切换设备不迁移任务。不同项目允许选择不同 Panel 版本，能力差异由 Host 显式声明。

- 电脑本地项目：电脑执行；云端服务离线不妨碍本地操作。
- 电脑云端项目：独立云端工作台登录，云端执行。
- 手机本地项目：配对并远程控制电脑；电脑离线时显示离线。
- 手机云端项目：直接登录云端；不依赖电脑在线。
- Link：独立管理第三方连接和受限授权；其故障只影响依赖该连接的功能。

## 仓库与部署边界

| 仓库 | 负责 | 不搬入的内容 |
| --- | --- | --- |
| `codeshell` | Core、Desktop、共享 Web、Panel Host、项目执行和连接基础包 | Panel 的模型、编辑规则、业务脚本 |
| `codeshell-panel-apps` | 六个 Panel、业务原生入口、客户端辅助库、独立版本 | Agent 引擎、服务器身份和主机权限 |
| `codeshell-services` | 独立 Link、云端控制产品入口、部署配置、运维工具 | Core 源码、桌面仍依赖的整个 `packages/server` |

服务仓库已在本地建立，但还没有远程仓库和公开发布。它通过固定公开包版本组合云端产品。拆仓库与拆部署单元分别安排；首版仍可在一台服务器部署。

服务器至少有三个独立运行单元：

1. **Cloud 控制服务**：账号、初始化、项目目录和生命周期、工作台入口、项目路由。
2. **项目执行环境**：各项目 Docker 容器和数据卷，实际运行 Agent、Panel 任务及程序。
3. **Link 服务**：第三方授权、下游应用授权、凭据加密和只读数据动作。

反向代理负责 Cloud / Link 各自域名与 HTTPS。电脑执行器属于桌面产品；后续安全中继是另一项连接能力，不能用 Link OAuth 服务替代。现阶段 Cloud 控制服务是宿主机 Node 进程，不直接套用单工作区 Compose。
