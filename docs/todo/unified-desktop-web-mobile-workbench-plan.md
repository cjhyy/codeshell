# 电脑 Web 手机与云端统一工作台规划

> 日期：2026-10-09。
> 状态：产品与实施规划，新增统一能力尚未实现；现有底座见第 10 节。
> 适用前提：用户已有部署好的 CodeShell 云端服务。首期面向个人账号与多台设备。

目标是让电脑、Web 和手机进入同一个个人工作空间，查看共享项目、对话、任务、审批和结果，并选择云端或已授权电脑执行。电脑继续保有本地文件、程序与独立工作能力。云端 Agent 也能把一个明确步骤委派给电脑，再取回结果继续工作。

## 1. 产品模型

必须分开两个用户选择：**共享范围**和**运行位置**。

| 选择 | 含义 | 示例 |
| --- | --- | --- |
| 共享范围 | 哪些内容进入个人空间、允许跨端查看 | 本机私有、共享摘要、共享对话与选定资料 |
| 运行位置 | 本次任务由哪个环境执行 | 云端项目、我的 Mac、另一台电脑 |

资料的实际存放位置还需要单独记录：文件可留在电脑，只把授权资源引用或选定副本放进个人空间。界面在附件、文件和结果处显示位置，不要求用户先理解内部存储结构。

由此形成三种常用任务：

- **本机私有任务**：保留现有本地工作流，内容留在电脑，不进入云端目录。
- **共享电脑任务**：手机、Web、桌面能看到同一任务；代码、浏览器及执行在指定电脑。
- **共享云端任务**：内容与执行在云端；电脑关闭后仍能从手机继续使用。

跨环境协作时，云端父任务与电脑子任务各自有明确执行位置；运行中的任务不会因为切换页面或设备而迁移。共享目录中的电脑离线时仍保留条目和最后同步状态。

## 2. 三端应有的体验

### 桌面

侧栏统一提供任务、项目、资料、设备和通知。本机私有内容保留明显入口；共享任务卡片持续显示“运行于我的 Mac / 云端”和同步状态。

现有“云端工作台填地址”升级为“连接个人空间”：填写服务地址、登录并关联账号，随后展示设备与共享目录。首次关联时选择哪些本机项目可被发现、哪些可远程执行、哪些内容可共享。以后通过已保存空间进入，无需每次填写地址。

桌面直接访问本机 Host，云端连接失效时本地工作仍可用。统一数据和导航契约即可，不要求先把 Electron 原生界面全部替换成 Web，也不把远端页面接上 unrestricted Desktop preload。

### Web

Web 提供共享工作台：统一查询、创建任务、继续对话、处理审批、看结果和管理已关联设备。选择电脑任务时，仍由对应电脑的 Host 校验项目和权限；选择云端任务时，交给相应云端项目。

现有设备目录和 `/mobile` 跳转可以作为迁移期入口，最终普通流程在统一工作台完成。深链使用稳定项目/任务引用，避免把不同环境中的同名目录当成同一项目。

### 手机

手机作为同级入口，首期采用响应式 Web，并提供可安装 PWA 的交付路径。首页优先呈现待我处理、进行中的任务和最近项目；主导航以任务、项目、资料、设备为核心，通知和审批从收件箱进入。

首期必须支持：

- 新建云端或电脑任务，继续共享对话、补充信息和取消来源支持的任务。
- 查看进度、执行位置、在线状态和结果；电脑关闭时照常使用云端任务。
- 处理审批，打开通知定位到同一任务或对应结果。
- 上传手机文件、相机照片；录音作为可追踪附件，有转写能力时再转成文本。
- 下载和预览支持的结果，选择把附件交给哪个任务及执行环境。

手机采集是设备能力，长期 Agent 执行放在云端或电脑。原生手机 App、系统分享入口和更深的手机设备操作作为后续独立增量；不以它们作为首期三端闭环的前置。推送与采集均按实际能力探测并做真机验收。

## 3. 共享数据边界

| 内容 | 处理方式与阶段 | 权威来源 |
| --- | --- | --- |
| 个人空间、已关联电脑、项目目录与可用能力 | 云端保存统一目录；电脑只发布已授权项目 | Cloud 账号/关联记录；Host 确认项目与能力 |
| 共享任务标题、状态、父子关系、审批计数、结果索引 | 跨端统一投影，记录版本和最后同步时间 | 执行 Host 的任务来源与审批存储 |
| 对话消息 | B：共享对话模式下有序同步；摘要模式只发布所选摘要 | 来源 Host 日志；云端保存授权副本 |
| 附件、明确发布的结果 | B：云端托管选定副本，记录来源和版本 | 共享对象存储及其版本记录 |
| 共享文档与项目记忆 | D：按项目共享策略版本化保存和处理冲突 | 共享对象版本记录；来源 Host 记忆存储 |
| 本地工作目录、未提交代码、进程、浏览器状态 | 留在所属电脑；按需传文件、产物或 patch | 所属 Host |
| 云端项目文件和后台任务 | 保留当前云端项目数据与执行边界 | 对应项目 Host |
| API key、cookie、SSH key、系统权限 | 留在所属环境；提供授权后的能力 | 所属 Host 或独立 Link 服务 |
| 模型、Skill、Panel 模板及版本偏好 | 后续共享可移植声明；每个 Host 校验安装和依赖 | 模板版本库；Host 的实际安装状态 |
| 草稿、滚动位置、临时录音和上传暂存 | 客户端保留原件/草稿；服务端或 Host 隔离暂存上传字节；正式登记后成为指定任务附件 | 客户端与隔离暂存；成功登记后转交对象权威来源 |

建议新关联项目默认只共享目录和任务摘要；完整对话、记忆及资料由项目设置开启。本机已有私有项目和历史不会因登录或登记设备而静默上传；历史回填要限定范围并可预览。标题、路径和摘要也属于共享内容，首次关联需说清楚。

摘要模式下不自动回填对话全文。Host 在线且当前入口获准时，可按需读取详情；离线时只提供已共享摘要。若需要跨端保留全文，应明确提升共享范围。继续对话、处理审批或委派电脑子任务，都不会自动扩大对话和文件的共享授权；子任务交付只包括获准结果。

逻辑项目可以关联 Mac 与云端的不同工作根目录。关联不触发整目录双向同步；文件交接显式采用上传、下载、Git、patch 或发布产物。并发编辑文档使用版本条件保存与冲突处理，不以最后写入静默覆盖。

## 4. 目标架构与现有系统的关系

统一工作台分为入口、云端协调和执行 Host：

1. **三端入口**：桌面、Web、手机消费同一目录、任务和审批契约。
2. **Cloud 协调**：账号关联、跨 Host 索引、持久投递、通知收件箱及共享对象目录。
3. **连接能力**：复用电脑出站连接和稳定中继；增加受限 Host 任务接口及权限声明。
4. **执行 Host**：云端项目和电脑继续运行现有 Engine、AgentBridge、任务来源、审批及资源服务。

本地已实现的 `task-inbox` 是统一任务模型的基础：复用 `taskKey`、来源去重、能力快照和动作路由；跨 Host 聚合键增加 `environmentId`，动作仍回到来源控制器重新校验。Cloud 的索引可以重建，不迁移 Session、Run、Cron、Mimi 或后台 job 的权威存储。

现有 `TaskInboxRecordV1` 仍含 `workspacePath`、内部错误及 artifact URI，不能原样上传或作为远端控制参数。需要单独的对外投影与版本化 Host DTO，过滤路径/内部字段，把产物转换成获授权资源引用。Host 动作接口也不能直接映射 renderer IPC。

身份至少区分：个人空间账号、环境、逻辑项目、该环境内的原生项目/根目录、任务来源及 attempt。执行目标绑定已有 `environmentId + projectId + rootId?`；逻辑项目只是关联，不替代 Host 对实际目录的解析。

账号登录负责发现和查看；执行权限由目标 Host 的授权决定。Cloud 和设备目录的同名账号不自动视为同一身份；通过一次性关联流程建立明确绑定。中继连接凭据、浏览器配对凭据和任务执行授权分别管理。

## 5. 任务投递与云端操作电脑

### 从任意入口向指定电脑或云端发起任务

用户选项目和运行位置后，系统固定本次目标，生成持久请求 ID。Cloud 记录投递意图，目标 Host 校验账号授权、项目、能力、配额和有效期，持久保存受理回执，再交给已有执行链。

界面区分“已提交、等待电脑、已受理、运行中、等待审批/输入、收尾、完成/失败/取消、结果待核实”。断线是连接状态，不直接把 running 改成 failed。

重复请求 ID 返回同一受理结果；同 ID 的不同参数拒绝。已有任务能力按来源展示，历史 Run 不会因为进入统一工作台就获得取消或恢复按钮。投递回执必须跨进程持久化，不能只靠内存去重或短期进程回执。

Host 受理前以 `requestId` 跟踪投递；受理后持久关联 `requestId → environmentId + taskKey + attempt`。界面从等待电脑到运行中保持同一条目，关联既有权威任务，不额外制造一张重复任务卡。

### 云端父任务委派电脑子任务

示例：手机提出需求 → 云端分析 → Mac 指定项目完成改代码和测试 → 发布测试结果/patch → 云端接续整理交付。

首期跨 Host 委派采用完整子任务：请求指定电脑、项目、任务目标、允许能力、预算和可交付结果；电脑用本地 Agent 与原有工具审批执行。父子任务各有稳定身份和独立状态，主界面合并展示关系。

先提供通用任务委派接缝，复用已有子任务和结果唤醒路径。逐个远程透传任意 shell/工具调用，以及持续桌面操控，待明确消费者和控制范围后另做能力扩展。已有浏览器或桌面操作能力是否可用，由目标 Host 声明和系统授权决定。

父任务重启后重新附着原子任务；投递响应丢失时先查询受理回执，不创建第二份。父任务取消会请求取消子任务，只有执行 Host 确认停止后，子任务才显示已取消。

### 跨环境续做

另开目标 Host 的新 attempt，交接选定消息、任务摘要、附件和 patch，并保留关联。目标重新验证目录、依赖、模型与权限；不承诺迁移运行中的进程、系统登录态或工具句柄。

## 6. 手机审批 通知与附件

审批事实保存在执行 Host，绑定任务、具体动作、版本与有效期。三端同时处理同一审批时，Host 原子接受第一个有效回答，其余返回当前结果。权限或任务代次变化后旧审批失效。电脑首次授予辅助功能、录屏等系统权限，仍需在电脑完成。

通知以持久收件箱为可靠入口，按事件 ID 去重；推送是提醒增强，不充当任务状态来源。优先推送需要用户处理、完成和失败；进度更新留在任务时间线。链接打开对应任务、产物或审批，服务端再次检查权限。

附件上传前固定目标任务、项目和接收 Host；页面切换不改变目标。先进入只供此次上传访问的隔离暂存区，完成后登记为可查询附件，再交给执行 Host。未登记字节不能被其他任务读取；暂存有额度、取消清理和过期回收。响应丢失时查询原上传/附件 ID，不重复登记。跨端可见不代表自动复制到每台设备。

## 7. 离线 撤销与自动化

| 情况 | 应有行为 |
| --- | --- |
| 云端不可用 | 桌面本地运行照常；共享事件进入本机持久待同步队列，恢复后补报 |
| 电脑离线 | 云端任务继续；新电脑任务可明确选择等上线并设截止时间，或立即返回不可执行 |
| 手机离线/切后台 | 保留草稿及最近状态并显示时间；恢复后对账，未确认指令先查询结果 |
| 任务运行中断网 | 执行 Host 按授予策略继续或等租约恢复；结果持久保留；不自动换机器重跑 |
| 已受理后进程崩溃 | 来源恢复并对账；无法确认的状态进入“待核实”，不静默重新启动 |
| 多设备同时操作 | 来源版本校验、审批首个有效回答生效、消息/事件按 ID 去重 |
| 撤销设备/项目授权 | 立即停止新投递和结果访问，目标在线时停止相关授权运行；离线时显示停止待确认 |

远端即时停止与无限离线继续不能同时保证。远程委派任务如要求失联后也停止，使用有限执行租约；本机自行发起的任务保留本地策略。重连按游标补齐，游标失效时重新取快照；过期连接和旧授权版本不能投递或覆盖新状态。

每条自动化只有一个调度权威。已有电脑自动化仍由电脑调度；云端创建且目标为电脑的自动化，由云端生成唯一 occurrence ID，再走同一投递链。统一列表合并展示，不让两边重复触发；变更调度归属须先停旧调度。

## 8. 实施顺序与交付门槛

每一阶段都包含桌面、Web 和手机，不把手机留到最后。首个完整版本应完成阶段 A–C；阶段 D 丰富共享资料，阶段 E 扩大续做与设备能力。下列是顺序与边界，不是工期承诺。

| 阶段 | 交付内容 | 可验收的结果 |
| --- | --- | --- |
| A 统一入口与只读目录 | 核对已有部署版本与能力；关联账号/设备；导出 Host 任务投影；云端聚合；三端任务/项目/设备列表；共享摘要策略 | 同一个共享电脑任务三端同 ID、同状态；私有内容不上传；离线显示最后同步时间 |
| B 跨端操作闭环 | 持久投递与受理回执；手机/Web 直接创建云端或电脑任务；继续对话；审批与通知；附件和结果回传 | 手机发电脑任务、审批、取回结果；电脑关机后手机云端任务仍完成；响应丢失不重复启动 |
| C 云端委派电脑 | 云端父任务与电脑子任务关联、等待/结果唤醒、取消、预算和权限；重启重新附着 | 云端分析→电脑执行→云端交付在同一父任务可追踪；断网/重启无重复子任务 |
| D 共享资料与配置 | 共享文档/项目记忆版本、模板、选定文件/patch、模型/Skill/Panel 声明；按 Host 校验依赖 | 文档并发有冲突提示；声明不可用时明确原因；密钥不随模板分发 |
| E 续做与设备体验 | 显式跨 Host attempt 交接；更多 Panel 手机业务流程；更深原生移动接入与受限设备操作 | 交接可追溯且不迁移进程；真实手机采集、下载、推送与弱网闭环通过 |

阶段 B 的附件、会话和结果流属于最小共享闭环，不能推迟到 D 才让手机看到结果；D 才扩展成完整资料产品。电脑自动化的统一呈现进入 A，远程投递复用 B，跨 Host 自动化的可靠性随 C 验收。

每阶段同步完成独立能力开关、兼容探测、持久化迁移、备份恢复与回滚路径。真机和真实部署验证作为交付门槛，不用页面模拟或源码构建替代。

## 9. 仓库职责与迁移

| 范围 | 负责内容 |
| --- | --- |
| `codeshell-services` | 个人空间与设备关联、任务索引/投递、共享对象目录、收件箱、Cloud 协调和中继部署 |
| `codeshell/packages/server` 与 Desktop main | 版本化 Host facade、能力发现、出站连接、任务受理回执、审批/文件/资源授权适配 |
| `codeshell/packages/core` | 保留通用执行和持久任务生命周期；确有缺口时增加通用跨 Host 委派接缝 |
| `codeshell/packages/web` 与 Desktop renderer | 三端共用视图模型、查询和交互契约；手机布局与能力适配 |
| `codeshell-panel-apps` | Panel 的业务文档、数据 schema、模型和编辑规则；逐个接共享对象与手机业务能力 |

迁移保留已有地址书签、独立登录/配对、本地任务 ID 和项目存储。先读取能力，再启用索引、投递和委派；旧 Host 可继续原入口使用。不因这项规划先重写全部 Panel、合并所有权威 store，或建第二套执行引擎。

本次规划把统一目录、选择性共享和跨 Host 调度列为明确目标，扩展了[原本地/云端计划](project-cloud-panels-plan.md)中分离环境入口的首版边界。旧计划的已有交付继续复用；其“自动同步/跨主机迁移不列首版”的历史范围，不能用于否定本次新增目标。整目录无差别同步和运行中进程迁移仍不作为本方案承诺。

## 11. 完整版本验收场景

1. 桌面创建共享 Mac 任务，手机能继续对话、审批，并看到同一结果和执行位置。
2. Mac 关闭，手机直接创建并完成云端任务。
3. 手机选择 Mac 项目操作本地文件，结果明确来自 Mac；未授权目录不可访问。
4. 云端父任务委派 Mac 子任务，结果回到父任务；父进程重启不重复创建子任务。
5. 手机上传照片/文件，切换页面后仍只进入提交时选定的任务和授权目标。
6. 三端同时打开审批，只有一次有效回答和执行。
7. 投递响应丢失、重试及重连后，同一请求只启动一个任务；不明副作用进入待核实。
8. Mac 断网继续获准任务，恢复后事件按游标补齐且终态不回退。
9. 本机私有任务、历史和未授权项目不会因为账号关联而上传。
10. 撤销后旧连接、旧票据和旧审批不能发起新操作；离线停止显示真实确认状态。
11. 两台电脑/两个云端项目的名称或目录相同，任务、审批和产物仍不会混淆。
12. Cloud 停机时桌面本地功能继续可用；手机弱网/后台恢复后草稿不丢、状态可收敛。
13. 同一自动化 occurrence 不在云端和电脑重复调度；暂停定义与取消运行明确区分。
14. 备份恢复/降级后保留任务权威记录，重建索引，并使过期远程授权失效。

规划的默认取舍是个人账号、多设备、显式项目授权与响应式手机入口。团队租户、任意整机遥控、全量磁盘同步和原生手机常驻执行器分别评估，不阻断上述完整版本。
