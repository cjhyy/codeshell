# 项目记忆复制到数字人

状态：2026-10-10 已实现并通过本地分片、类型、构建及实际 macOS Electron 流程；最终 CI 与合并状态见 [PR #126](https://github.com/cjhyy/codeshell/pull/126)，尚未发行。

## 使用流程

在现有项目记忆页打开一条手动记忆或整理记忆，选择“复制到数字人”。选择目标数字人后，可以修改名称、摘要、类型、正文和置顶状态；审阅来源、目标及最终内容，再确认复制。

复制会创建目标数字人的新手动记忆，原项目记忆保留。目标未启用可移植记忆时仍可保存，页面明确提示暂不参与使用；本操作不启用该设置。目标启用后，记忆沿用现有 Profile memory 注入路径。

## 写入边界

- Main 对预览和提交分别重新授权项目路径。审阅记录绑定发起窗口、规范化项目、源记忆、目标数字人定义和最终编辑内容。
- 审阅记录短期有效、只能提交一次。源或目标发生变更、审阅过期或跨窗口使用时拒绝提交，要求重新审阅。
- 目标同名记忆阻断复制，保留编辑内容供用户改名；目标采用新 ID，不覆盖已有条目。
- 来源整理记忆只复制审阅后的内容，不携带原有 dream 生命周期或自动管理标记。不会自动整理、调用模型或修改自动 dream 策略。
- 沿用现有 MemoryManager 的文件写入和索引能力；不声称与所有其他进程的 Core writer 形成全局事务。
- 文件身份、大小和版本预检有数量与字节限制；既有 MemoryManager 解析仍会重新读取文件。这不是对同时修改本机文件的其他进程提供严格的解析资源隔离。

## 原有记忆与后续运行

项目的 user／dream 条目可以作为来源，包含无显式 ID 的旧条目以及空摘要、空正文。来源 pending、全局记忆和其他数字人的记忆不通过这个入口复制。旧平铺目录先由原有记忆编辑器迁移，预览自身不触发迁移。

副本只包含本次编辑的名称、摘要、类型、正文和置顶状态，创建新的 ID 和手动所有权；命中次数、更新时间和 dream 的提升／来源项目标记不沿用。数字人未启用长期记忆时明确显示“仅保存”，不会切换当前 Profile、修改开关或重启已有 Run。后续使用该数字人的运行仍沿现有 Profile 选择和 PromptComposer 的注入规则。

本次不增加入口或侧边栏，不自动提取经验，不调用模型，不修改自动 dream 对 portable profile memory 的写入限制。受约束的数字人 dream ownership／审批合同仍保留为后续事项。
