# 全部 Panel 的服务端完整可用性方案与验收矩阵

日期：2026-09-18。状态：实施中；以下全量 Panel 工作流验收尚未运行。
主方案：[Panel Host 整合与服务端隔离](panel-host-integration-and-server-isolation-2026-09-18.md)。

实施进展（同日）：CodeShell 分支 `codex/panel-host-0920` 已接通 Web `tasks.*` 与事件桥，并通过真实 Node 工具的运行、页面关闭后恢复、会话撤销和项目版本只读测试；Web 服务端目录书签也能在面板重开后恢复。这是 P2a 与目录能力的局部实现，尚未做真实 Docker 项目验收，也不改变下述整体验收状态。Docker 已启动，但构建基础镜像时远端拉取停滞，容器用例仍待运行。Chrome 实测发现，即使改变 `frame-src`，外层 `sandbox="allow-scripts"` 仍使设计面板的内层 `srcdoc` 无法从 Panel 页面读取；不能靠放宽 CSP 一项解决。

## 1. 目标与完成标准

用户要求：每一个现有 Panel 都能在服务端用起来，并达到桌面端对应功能的使用效果。首期面向个人或可信小团队自托管。

验收单位是“Panel 的实际功能与完整用户流程”。打开页面、成功安装、声明 API 14、展示部分可用提示，都不能证明该 Panel 已经可用。桌面端已经能完成的功能，Web 必须提供可完成相同目标的操作流程；涉及本机与服务器位置差异时，明确选择、上传、浏览、下载或登录的位置。

所有业务 Panel 都进入首期范围。模板也需要基本兼容验收。实现先后可以分批，但不能只挑几个简单面板通过就结束。隐藏缺失功能、只提示回到桌面端，也不计为该项通过。

两项必须纠正的旧结论：

- Mimi Download 0.20.0 的主队列和历史已经使用 Host `storage.get/set`。旧源码和旧验收记录中的“下载历史全部丢失”不能套用到该版本；仍需处理的是特定偏好、临时搜索恢复及真正的运行验收。
- 视频工作台 0.6.9 已经含客户端 SDK、resources 与原生后台任务适配。整合应先定位对应源码并复用已有实现，再推广到其他 Panel，不能根据旧 0.4.9 工作区重复建设 SDK。

预览用 mockHost 的 localStorage 与真实 Host 路径要分别分析，不能只搜索到这个词就判定面板不能持久保存。

## 4. 三个实施面

### A. 可信浏览器工作台适配

| 用户操作 | Web 实现要求 |
| --- | --- |
| 选择本机文件/文件夹 | 浏览器选择并上传；目录能力按浏览器支持范围处理，不能把服务器 downloads 伪装成本机选择器 |
| 浏览服务器文件/打开输出 | 受控目录浏览、预览与鉴权下载；保存后核对实际文件，不只返回服务器路径 |
| 麦克风、摄像头、录屏 | 可信工作台在用户操作下发起浏览器授权与采集，向 Panel 交接有限事件/资源；结束、取消、关闭与撤权时释放设备 |
| HTML 导入/布局测量 | 提供受控渲染/测量环境，与可信父页面分离；限制脚本、网络、文件和导航，验证导入数据的渲染结果 |
| 音视频预览 | 支持鉴权流式读取和 Range、拖动定位与错误恢复；短期资源授权不扩大成工作区读权限 |
| PDF/文件导出 | 导出当前编辑内容的稳定快照，携带匹配的样式、字体和资源；交付浏览器下载入口 |
| 提示、结果与通知 | 操作状态及错误能持续查看；需要桌面基线的浏览器后台提醒时提供明确订阅与权限流程，并单独验证离线场景 |

当前 iframe 和响应策略禁止 camera/microphone/display-capture，HTML 的 `frame-src 'none'` 也限制子页面。方案应新增受控适配，不能整体移除沙箱或给 Panel 添加全部权限。设备采集依赖安全上下文与用户授权；HTTPS 部署、浏览器支持和设备可用性都需验收。[getUserMedia 约束](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[frame-src 语义](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-src)。

HTML 转领域文档、图层识别与编辑规则仍由设计 Panel 实现；Host 只提供复用所需的通用受控渲染边界。服务端不能在可信工作台直接执行导入 HTML 的脚本。

### B. 服务端 Host 能力补齐

| 能力 | 处理方式 |
| --- | --- |
| 原生后台 `tasks.*` | 接通已有持久服务；关闭页面继续，撤权/取消/项目停止按已定义语义处理 |
| `automations.*` | 在项目 Host 装配 Core 自动化机制、持久配置和事件；记录项目停止时暂停/错过的触发，重启不盲目重放有副作用任务 |
| 服务器登录与 Cookie | 项目独立的浏览器登录会话、凭据托管、显式选定账号及密封进程交接；支持的网站可走 Link/OAuth；用户明确导入凭据作为适用场景的辅助入口 |
| 转写 | 采集在客户端，服务端接受获准音频资源后调用转写适配；配置、进度、取消和失败可见，模型/业务规则属于 Panel |
| media 兼容 | 保留旧资源/文档 ID、版本和历史读取；通用机制复用 resources/tasks，业务处理保持 Panel 原生入口 |
| 目录与书签 | 补 project 目录能力、服务端选择及书签恢复，使用时重新校验项目和目录身份；与浏览器设备目录授权分开 |
| 渲染、预览及 PDF | 接通真实数据快照与资源访问；限制渲染进程的网络和文件权限；执行在项目环境，结果回到资源托管 |
| 运行依赖 | 每个 Panel 列出实际程序/库、版本、架构、模型和网络需求；安装与缓存策略归 Panel，Host 提供通用执行能力和诊断 |

浏览器页面不能自动取得用户电脑其他网站的 Cookie。需登录流程必须明确登录发生在哪里，并实际验证选定账号可供对应任务使用。Cookie 导入兜底不能自动等价于桌面所有登录/恢复流程已经通过。

“已声明 permissions”与“相关按钮所需能力齐备”不是同一件事；例如 workspace.write 不代表 Web 实现了 exportPdf。现有 compatibility 固定 `supported:true` 只能说明允许加载，应补充按功能的静态需求与运行时检查，分开展示“可加载、待配置、待适配、已验证”。

### C. 各 Panel 与共享客户端适配

1. 复用当前已安装新版所对应的 SDK/任务适配源码；以小步迁移统一能力探测、结构化错误、事件和预算驱动队列。
2. 将真实运行路径的持久化统一到授权 Host 存储/文档；迁移可恢复旧数据，不删除已有队列、工程和草稿。
3. 以具体 `availableMethods` 与平台能力选择完整流程，不依赖 API 数字、macOS 路径或是否存在某个全局对象来推断全部支持。
4. 修改设备采集、HTML 测量、文件导出等业务调用，使其使用新的适配接口；不能只补 Host 方法而保留原先被 iframe 禁止的浏览器调用。
5. 对于确需增加的通用接口，制定权限和限额并以可选能力演进。保留旧 API 14 已有行为；安装包、独立仓库和 Host 的发布版本一起进入兼容矩阵。

## 5. 全量验收与发布门禁

每个功能用例记录：Panel ID/版本/来源与摘要、Host/Web 版本、运行 revision、镜像 digest、操作系统/架构、浏览器、配置与所需授权、输入样本、操作步骤、截图或录屏、真实结果文件与校验、持久化恢复结果。凭据不写入记录。

| 验收项 | 判定要求 |
| --- | --- |
| 界面 | 相同输入、主题与视口对照 Desktop/Web；画布、布局、字体、控件、弹窗、滚动、拖拽与关键编辑结果正确 |
| 执行 | 点击真实操作，进度与状态来自实际任务；输入→执行→输出链路完整，模拟结果不能替代真实依赖验证 |
| 导出 | 浏览器实际保存文件，检查内容、格式与摘要；PDF 核对当前文档、分页和字体，媒体核对可播放/时长/字幕等基线结果 |
| 持久化 | 页面关闭重开、刷新、断线重连、Host/项目重启后按承诺恢复；会话权限与跨项目隔离保持 |
| 任务生命周期 | 取消真正终止；重复请求不重复启动；设备/登录撤销行为明确；项目停止后的中断不冒充成功 |
| 外部能力 | 所需模型、登录账号、网站或数据源按支持范围真实验证；尚无凭据记“待授权验证”，不能记“通过” |
| 性能 | 固定样本记录加载、编辑、预览定位、传输与任务用时；P0 根据桌面基线和目标服务器确定预算，避免只用小文件证明大型工程可用 |
| 部署 | 目标服务器运行的 Host、Web 资源、镜像和 Panel 包与验收版本一致；保留数据迁移和回滚记录 |

开发阶段可使用固定夹具和替身提高重复性；发布前必须对每个业务 Panel 跑真实工作流。没有模型密钥/站点授权的案例保持“待验证”，受支持场景未实现保持“待适配”，都不计入已完成。

桌面与浏览器不必使用同一种系统窗口，但用户应能完成同一件事。例如桌面“在 Finder 中显示”在 Web 对应“服务器文件浏览并下载”，而不是返回一个用户无法访问的路径；录音使用访问网页的电脑麦克风，而不是服务器设备。

首期完成条件：P0、P1、P2a–P2d 全部完成，六个清单项的完整用例通过，实际部署版本对账完成。任何一个业务 Panel 缺关键流程，首期都仍未完成。
