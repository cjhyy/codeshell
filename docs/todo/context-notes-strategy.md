# 会话工作笔记与新上下文（首版）

CodeShell 原生引擎增加 `notes` 上下文策略：让正在执行任务的模型维护一份接续笔记，在适当时机换一段有效上下文，并按需查回本会话历史。Mimi 默认使用这个策略；普通 Session 暂时保留 `summary` 默认值，可以通过配置选择 `notes`。

这是 CodeShell 自身的能力，不依赖 Codex 账号，也不控制 Codex CLI 等外部运行时的上下文管理。

## 用户能感受到的变化

- 长对话继续留在同一个 Session 中。切换的是发送给模型的有效上下文，不会新建工作会话、替换会话身份或删除完整对话历史。
- 笔记保存当前目标、用户的重要纠正与约束、已做决定、相关任务引用、未完成事项和下一步。模型不必每次把全部旧对话重新读一遍。
- 缺少某个历史细节时，模型可检索当前 Session 的记录。搜索结果只用于补充背景，当前用户输入、工具结果和宿主提供的实时任务状态优先。
- Mimi 的工作笔记与长期 `Memory` 独立：工作笔记回答“这件事做到哪里了”，Memory 保存长期偏好和事实。笔记不提供额外权限，也不是任务进度的权威账本。

## 配置

在项目的 `.code-shell/settings.json` 中选择普通会话也使用笔记策略：

```json
{
  "context": {
    "strategy": "notes"
  }
}
```

使用原来的摘要策略，包括让 Mimi 回退：

```json
{
  "context": {
    "strategy": "summary"
  }
}
```

未设置 `context.strategy` 时，Mimi 的行为配置默认选择 `notes`，普通会话默认选择 `summary`。显式设置会覆盖行为配置的默认值；删除该字段即可恢复各自默认值。首版通过配置接入，不新增设置页开关。

SDK 宿主也可在创建 `Engine` 时传入 `contextStrategy: "notes"` 或 `contextStrategy: "summary"`。完整优先级为：SDK 显式配置 → 生效的 `context.strategy` 设置 → `RunBehaviorProfile.contextStrategy` → `summary`。设置文件是否生效仍由宿主现有的设置作用域决定；`isolated` 不读取磁盘设置。

## 一次接续怎样发生

1. 模型在有重要变更时调用 `SaveContextNote`，保存一份完整、简洁的当前工作笔记。
2. 在阶段结束或收到上下文预算提醒时，模型先保存最新笔记，成功后才调用 `NewContext`。
3. 引擎在工具调用完成的边界切换有效上下文，以笔记和必要的近期内容接续。Session 身份、原始历史和宿主管理的状态继续保留。
4. 如果笔记不够回答某个问题，模型通过 `SearchHistory` 查当前 Session 的历史，再继续处理。

引擎会在接近压缩阈值时提前提醒模型留存笔记。达到阈值后优先尝试通过有效笔记接续；笔记缺失、无法安全切换或模型没有及时配合时，现有的摘要／窗口管理继续承担兜底，避免只因为笔记不可用就中断工作。

这三个工具只在启用原生 `notes` 策略时可用。使用 `summary` 的会话沿用现有的上下文管理方式。

手动压缩（包括 `/compact`）也遵循当前策略：`notes` 模式下有可用笔记时优先接续，否则回退到已有摘要压缩。首版从磁盘恢复的笔记切换标记不重建当时的 token 差值；实时压缩事件仍携带本次的估算值。

## Mimi 的使用约定

- 重要纠正、决定或待办变化要在回复前保存，尤其是会结束本轮的 Gateway 回复或主动消息工具之前。
- 普通问候、简单确认或没有变化的状态无需更新笔记。一次合并保存相关变化，避免每句闲聊增加工具调用。
- Mimi 保留每轮最多 6 步的管理边界；先完成必要的管理动作，笔记记录真实结果，并为最终回复保留空间。不要在同一轮反复切换上下文。
- 查历史不能代替查询实时任务状态。历史里的任务引用需要通过现有管理工具核对；笔记本身不会创建订阅、改变授权或恢复某个工作会话。

## 首版边界与评估

这个策略省掉的是正常接续时独立的全历史总结调用，不代表零 token 压缩。模型写笔记、注入笔记和检索历史仍会消耗 token；缓存效果和应急摘要也会影响总成本。

首版优先验证连续多次接续后是否保留用户纠正、未完成事项和准确的任务引用，同时观察工具调用数、接续失败／摘要兜底频率与总 token。自动化测试只能确认机制和边界，真实模型的笔记质量、连续长对话体验及成本收益仍需实际使用评估。
