# CodeShell 视频工作台：产品与架构草案

状态：2026-09-07 的产品与架构讨论稿，保留原设计背景；截至 2026-09-11，Host 媒体能力已实现，当前契约见 [Panel 媒体 API](../panel-media.md)，本文不作为全部视频工作台功能已完成的声明。

## 产品目标

让用户和 AI 共同编辑同一份视频工程。用户用鼠标选择片段、拖动时间轴、修改字幕；AI 读取当前选择和工程版本，把自然语言要求转成可检查、可撤销的剪辑操作。交付既包含 MP4，也保留可继续编辑的工程。

建议首个场景是录屏教程和产品演示，直接用本次 CodeShell 教程及一段真实录屏做验证。先建立素材导入、播放、剪辑、保存、导出的完整流程，再加入 AI 粗剪、文字剪辑和自动包装。

## HyperFrames 在这次教程中的实际工作

1. SCRIPT.md / script.json 保存 46 段口播和画面要求。
2. 生成分段配音，测量实际时长，据此建立时间轴和字幕。
3. HTML/CSS 重建界面，GSAP 编排鼠标、点击高亮、输入和状态变化。
4. HyperFrames 按时间采样画面，进行预览、检查和视频渲染。
5. 本次最终采用标准截图模式分章并行导出，再用 FFmpeg 合并画面、配音和章节信息。

这是代码生成的模拟操作画面。真实录屏仍需另外采集和导入。程序化场景适合标题、图表、讲解卡片、字幕动效、鼠标提示和可重复生成的 UI 演示。

## 工作界面

- 宽面板模式：上方视频预览，下方多轨时间轴。
- 侧栏按素材、口播文本、字幕、样式、导出任务切换。
- AI 使用 CodeShell 现有对话；当前选择、时间范围、播放位置和锁定轨道可成为对话上下文。
- 选中片段后说“这段缩短一半”“只保留成功的操作”“这里放大右上角按钮”，由同一套剪辑命令修改工程。
- 每批 AI 修改显示具体变化，可撤销，也可保留一个候选版本比较。

## 值得做的 AI 能力

| 阶段       | 用户表达                                | 可检查的产物                                 |
| ---------- | --------------------------------------- | -------------------------------------------- |
| 整理素材   | 找出讲安装配置的部分                    | 带源文件和时间范围的素材片段，附缩略图与转写 |
| 粗剪       | 去掉长等待、重复演示和明显口误          | 一个新粗剪版本，保留删除记录和原始片段       |
| 按文字剪辑 | 删掉这两句话，把这一段提前              | 音画联动的时间轴变更、重新对齐的字幕         |
| 教程处理   | 讲到按钮时放大操作区域                  | 有时间范围的缩放关键帧与指示层               |
| 字幕和声音 | 修正 CodeShell 等术语，配乐在人声时降低 | 字幕修订、带时间的音量变化                   |
| 动画补充   | 加一个解释 Goal 的章节卡                | 可重新生成的 HyperFrames 合成片段            |
| 多版本     | 从长教程做 60 秒竖版                    | 独立版本、重新取景和排版，主工程不被覆盖     |
| 交付检查   | 检查黑屏、缺音轨、文字裁切              | 可定位到时间点的报告与导出结果               |

“删除重复演示”“选择最佳片段”属于模型判断，应保留版本和原始时间范围。自动缩放若能读取录制时的鼠标/点击事件会更可靠；仅凭视频时需要视觉识别与可调关键帧。

## 人和 AI 共用的数据与操作

权威工程建议为版本化的 video-project.json。记录素材 ID/指纹、源入点出点、轨道位置、速度、音量、字幕、合成片段和导出参数；时间采用整数帧或明确的有理时间基准。转写、缩略图、波形和代理视频为派生缓存。

人工拖动和 AI 工具都调用同一个操作层。建议领域操作包括读取当前状态、搜索片段、拆分、裁剪、移动、删除范围、修改字幕、加入合成片段和提交导出任务。

每次修改带 baseRevision；批量变更原子应用，记录逆操作。用户在 AI 规划期间拖动片段导致版本变化时，重新检查和调整变更，不能覆盖人工操作。轨道锁定、音画联动、撤销/重做、自动保存和崩溃恢复属于基础能力。

AI 主要提交结构化剪辑操作，少量自然语言建议本身不算完成剪辑。导出完成要能定位结果文件，并核对音轨、时长和预期画面。

## HyperFrames 与常规剪辑的分工

普通录屏、摄像素材和音频使用常规剪辑能力。HyperFrames 承担可参数化的程序化场景，并作为复合片段加入主时间轴；保留源工程、参数、渲染版本及缓存。

第一版支持明确的场景类型和模板参数。任意 HTML/GSAP 反向转换成可任意拖动的图层，不能视为现成能力。当前教程可先按章节或场景导入，再逐步开放标题、颜色、时长和内容参数。

预览与最终导出必须覆盖同一套操作语义。需明确支持矩阵，检查变速、裁切、字体、转场、音量与字幕的一致性。长视频要支持低清代理预览、分段渲染、缓存与失败章节重试，避免每改一句字幕重做全片。

## 已有 CodeShell 能力与缺口

已核实可复用：Panel App API v11、项目绑定、安装权限审查、manifest Agent tools、registerTool、agent.task、workspace 带版本写入、本地 process.find/spawn/cancel。Design Studio 的操作日志和 revision 检查可作为共享编辑逻辑的参考，Mimi Download 的依赖检测与素材流程可作为导入参考。

需要新增的 Host 能力：

1. 媒体服务：授权文件句柄、复制/引用导入、元信息、支持 Range 的媒体播放、缩略图、波形和代理缓存。现有 cspanel 协议服务安装包资产，MIME 未含音视频；不能用 JSON IPC/Base64 搬运 GB 级视频，也不应笼统放开面板网络权限。
2. 长媒体转写与对齐：当前 audio.transcribe 最大 25 MiB，返回文本，没有剪辑所需的时间戳。需异步文件转写、词/句时间、分块和恢复。
3. 持久任务：现有面板 process 最多 3 个并发，输出累计超过 4 MiB 会终止，guest 撤销时会结束进程。生产导出需由 Host 或媒体 worker 持有，关闭面板后继续运行；返回 job ID，提供查询、进度、取消、重试和结果路径。

领域 UI 与声明式工具放入 codeshell-panel-apps/apps/video-studio。媒体 worker 通过 Host 服务或独立 capability/plugin 接入。保持 Core 与视频领域解耦，遵守面板仓库禁止任意 backend/hooks 等进入 Panel App 包的约定。

## 实施顺序与验收

第一阶段：基础剪辑。导入真实录屏与音频，连续拖动预览，切分/裁剪/排序，自动保存，撤销，字幕轨与音频轨，导出可播放 MP4。能关闭面板后继续导出，重新打开找到任务和结果。

第二阶段：AI 教程粗剪。生成带时间的口播文本，支持选句删除、去静音建议、术语修正、章节划分和候选粗剪；人工修改与 AI 修改可交替且不丢失。

第三阶段：HyperFrames 场景与多版本。插入可编辑的章节卡/讲解动画，对选定操作区加放大关键帧，输出长版与竖版；修改局部只重算受影响部分。

首个验收案例：导入本次教程相关工程与一段真实录屏，产出一份可调整的精简教程和一份短版，保留源素材、可编辑工程、MP4 与 SRT。质量验收包括音画同步、字幕准确、修改可撤销、预览与输出一致、关闭面板导出不丢失。

## OpenCut 选型结论

截至本次核查，OpenCut 主仓库明确处于重写阶段，Editor API、MCP、无界面批处理与 Rust core 是列出的重写方向；经典版已归档且不再维护。这些方向值得参考，不能把计划功能视为当前可直接接入的稳定接口。

建议借鉴或复用成熟的时间轴交互和编辑命令设计，先通过真实素材导入、预览一致性、本地导出和 AI 命令事务四项技术验证，再确定是否采用其底层代码。CodeShell 的共享工程与媒体 Host 边界应独立成立。
