With two ordinary `user_prompt_submit` handlers at priorities 10 and 0, pause the first using an in-memory promise, then register a third at priority 20 and release it. The observed call sequence and aggregated messages are both `existing-high, existing-high, existing-low`; the new high-priority handler runs zero times in this emit although the registry contains all three afterward. The fixture is bounded and uses no clocks, native process, shell, Engine, model, or I/O hook.

Two controls pass: registering all three before emission calls each exactly once in descending priority; suspending and releasing the first without changing registration calls each original handler once.
