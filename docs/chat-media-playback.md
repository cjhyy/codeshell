# 聊天中的音视频播放

Desktop 聊天会将当前任务工作区中的音视频文件显示为播放器。支持 Markdown 媒体嵌入、普通文件链接，以及工具结果中识别到的媒体附件。例如：

```markdown
![配音](./output/voice.mp3)
[视频预览](./output/clip.mp4)
![带空格的录音](<./output/我的录音 01.wav>)
```

支持识别 MP3、M4A、AAC、WAV、OGG、Opus、FLAC、MP4、M4V、MOV、WebM 和 OGV。实际播放取决于 Electron/Chromium 对文件内编码的支持；文件扩展名不能保证可以解码。播放失败后可以重试，或用播放器右上角的菜单交给其他应用打开。

播放器不自动播放，也不预下载整个文件。接近可见区域时才准备播放入口，点击播放后通过分段请求读取媒体，支持进度拖动。开始播放另一段聊天媒体时暂停上一段；关闭工具卡、切换任务或关闭窗口会停止播放并释放入口。

本地访问由 Main 依据持久化的任务和项目根目录授权，前端不能通过传入任意工作目录扩大权限。路径失效、越界、符号链接或工作区身份变化时拒绝读取。媒体网址是临时的不透明令牌，不暴露磁盘路径。浏览器取消一次缓冲或拖动进度不会撤销仍有效的播放入口。

本功能当前接入 Desktop 聊天。远程媒体网址仍显示为普通链接；独立 Web/手机端尚未接入该播放器。转码、生成和编辑继续属于相应 Panel，不由聊天播放器处理。

## 验证

关键回归测试覆盖消息解析、任务权限传递、延迟加载、资源释放、文件变动、HTTP Range 和请求取消。运行桌面端到端测试前先构建 Desktop，并确保 `ffmpeg` 位于 PATH（也可设置 `FFMPEG_PATH`）：

```sh
bun run --cwd packages/desktop build
bun run --cwd packages/desktop test:e2e:media-playback
```

该测试使用临时用户目录、生成的 WAV/MP4 和持久化对话夹具，验证实际解码、进度拖动、任务切换、错误提示及窄窗口布局，不使用模型服务或现有用户会话。截图与结果保存在 `packages/desktop/out/media-playback-qa/`。
