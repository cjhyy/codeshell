# Web 面板

桌面端开启的 Web 和独立部署的 Hub 共用侧栏「面板」、GitHub 安装器和浏览器运行界面。Electron 原生窗口仍使用原有 Panel Host；浏览器已接入进程、独立 Agent Task 和面板工具回调，尚未覆盖原生宿主的全部能力。

本文描述 2026-09-09 的当前源码。本轮运行能力增量已构建并更新到本机 `http://127.0.0.1:8790`，原有账号和五个面板绑定保留。授权目录网页已在真实浏览器中打开，文件 HTTP 内容已校验；live Mimi 已完成初始化，显示本地工具就绪。尚未执行浏览器点击保存下载，也未在真实账号中发起模型请求或用户媒体下载。部署与测试证据见 [验收记录](todo/web-panels-validation.md)。

## 安装与打开

1. 打开侧栏「面板」，输入 GitHub 仓库地址。官方仓库为 `https://github.com/cjhyy/codeshell-panel-apps`。
2. 搜索仓库，选择面板，审阅版本、提交、权限、附带 Skills、Agent 工具和 Web 兼容说明。
3. 确认安装并绑定当前工作区，在已安装卡片上选择「打开」。仓库内多个面板可逐个审阅安装。
4. 后续使用「检查更新」重新审阅；解除绑定只影响当前项目，卸载影响这个宿主用户下的所有项目。

安装器直接安装包含 `.codeshell-panel/panel.json` 的完整面板包，不执行仓库的构建脚本或依赖安装脚本。分支和标签先解析为固定提交，实际安装必须匹配审阅过的文件。预览有期限，并绑定发起安装的登录设备；审阅文件快照或已安装版本不再匹配时必须重新预览；分支前进不影响安装已经审阅的提交。

面板目录与 Desktop 共用宿主用户的 `~/.code-shell/panel-apps`，项目绑定使用已有的 `panelAppBindings`。同一台电脑、同一系统用户运行 Desktop 和 Node Hub 时，已经安装的面板可以直接绑定，不需要覆盖已有本地开发版。Docker 下目录位于持久数据卷中的 `/data/home/.code-shell/panel-apps`；容器与本机的已安装列表不会自动同步。

## 当前可用能力

| 能力 | Web 行为 |
| --- | --- |
| 面板界面 | 隔离 iframe 加载已安装包中的 HTML、样式和脚本 |
| 上下文 | 按权限提供工作区、会话、主题和可用方法 |
| `storage.*` | 面板与项目隔离的持久键值存储；Desktop Web 与原生窗口共享 Electron 用户数据目录，独立 Hub 使用自己的 `<data-dir>/panel-app-storage` |
| `workspace.info/list/readText/writeText` | 宿主上的工作区信息、目录和有限文本读写；写入检查文件版本，拒绝盲目覆盖 |
| `agent.submitPrompt` | 在可信工作台中确认后提交到当前会话；已有草稿、附件或运行中的任务会阻止提交 |
| `process.find/info/spawn/cancel` | 查找宿主程序、读取进程能力、启动与取消面板进程；执行前在可信父页面审阅并确认可执行文件和操作，输出与退出事件回传面板 |
| 受控目录与下载 | 获取或选择宿主提供的目录；打开目录时显示服务器路径和「查看并下载文件」链接，用户点击后在新页浏览经过鉴权的文件列表 |
| `agent.task.models/start/list/get/cancel` | 查询模型、启动与管理独立面板任务；任务内部需要批准的操作在可信父页面确认，状态事件回传面板 |
| 面板 Agent 工具 | 注册与注销面板声明的工具；Agent 调用经 `tools.invoke` 事件进入面板回调，结果通过父页返回宿主。主 Hub 会话也可调用这条链路 |
| `external.open` | 工作台确认后打开 HTTPS 链接 |
| `notifications.send` | 在工作台显示通知 |
| 附带 Skills | 使用 Core 原有发现机制，遵守项目绑定与启用策略 |

面板应以当前上下文的 `availableMethods` 判断具体方法是否可用，不能只凭 `apiVersion` 或安装成功判断功能齐全。Cookie 登录、麦克风与音频、媒体处理与采集、自动化、PDF 导出等能力仍未完整接入；声明这些能力的面板会显示「部分功能可用」及具体缺项。可执行程序和依赖必须存在于实际宿主中：Node 部署指服务器，Docker 部署指容器，不会使用浏览器所在电脑的程序或登录态。

当前安装的 Mimi Download 使用 `localStorage` 保存下载历史，且其权限清单没有声明 `storage`。Web 面板运行于隔离来源的 iframe，不能使用这种浏览器本地存储；历史只在本次打开期间显示，重新打开会归零。已下载的文件仍保存在服务器上，但文件落地不能替代面板任务与历史的持久保存。本轮没有修改外部面板清单或已安装副本；面板后续需要声明相应权限并改用宿主提供的 `storage.*`。

面板实例在到期前 60 秒续租，恢复页面时重新检查；成功续租保留同一 iframe 和面板内的输入。父页每秒拉取事件并按游标交付，临时网络错误会重试并保留页面；登录失效、授权撤销、事件积压失效或最终到期时，显示明确的重新打开入口。`host.confirm` 只在可信父页显示，不交给面板脚本自行批准；确认超时或取消不会伪报执行成功。

## 实现边界

`packages/server/src/panels` 负责共用管理、运行实例、进程与任务服务；`packages/web/app/HubPanels.tsx`、`PanelHost.tsx` 和 `panel-runtime-connection.ts` 负责共享界面、可信确认与运行连接。两种宿主保留各自的身份认证、工作区授权和 Worker，只向共用服务传入已经授权的上下文。面板配置修改遵守宿主任务门禁并热更新原 Worker。

面板脚本在不带 `allow-same-origin` 的 iframe 中运行，通过限定方法的消息桥调用父页。父页检查窗口来源、隔离来源和实例 ID；工具结果还必须匹配已交付的调用 ID，限制大小并只接收一次。HTML 与模块由短期、仅限面板静态文件的随机访问凭证提供；该凭证不授予管理 API 或任意工作区文件访问。退出登录、撤销设备、解绑、更新和卸载会使对应运行实例失效。消息桥不会把登录 Cookie、模型密钥或 Link token 传入 iframe。

浏览器隔离、进程确认和目录检查不等于完整的操作系统沙箱。进程在宿主环境执行，仍需审阅实际可执行文件和请求；当前实现不宣称具备完整网络隔离或覆盖原生 Panel SDK 的全部安全边界。

部署升级需要重新构建并重启 Hub；Desktop Web 还需重建 Desktop 并重启桌面应用。详见 [Node 部署](deployment.md)、[Docker 部署](docker-deployment.md) 和 [原生 Panel Apps](panel-apps.md)。
